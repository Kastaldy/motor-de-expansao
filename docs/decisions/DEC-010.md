### DEC-010 — Resolução de endereço por fetch HTTP na barra de busca do dashboard (BLK-UI-08)
- ID: DEC-010 | Data: 2026-06-17 | Criticidade: **Alta** (desvia do guardrail §2 "não criar dependência de API ao vivo no dashboard de produção"; READ-ONLY sobre o M1).
- Status: **APROVADA pelo usuário Vinicius em 2026-06-17.**
- Decisão: permitir, **restrito ao caminho de resolução de ENDEREÇO da barra de busca por coordenada** do dashboard (`render_coord_search_sidebar`), uma requisição HTTP leve para converter texto livre (endereço) em coordenada. O campo aceita tanto `lat,lng` quanto endereço; o caminho numérico (`parse_coordinate_input`) é SEMPRE tentado primeiro e fica INTOCADO; só quando ele falha o texto é tratado como endereço e resolvido por `resolve_endereco_http` (helper novo em `src/motor_expansao/api/maps_geocoder.py`, **`urllib.request` puro, sem Selenium**), que segue o redirect da URL de busca do Google Maps e extrai a coordenada via `extract_any_coord`, validando o bounding box do Brasil. Escolha do humano = **Alternativa B** (fetch automático) com fallback gracioso para o link clicável da Alternativa A.
- Justificativa: o operador quer digitar um endereço e cair direto no hexágono, sem o passo manual de copiar a coordenada do Maps. O desvio é local à busca e não afeta o restante do dashboard.
- Provedor / atribuição / anti-PII: Google Maps (busca pública via redirect). **O endereço digitado é ENVIADO ao Google** para resolver a coordenada — registrado aqui e exibido como aviso curto no campo de busca (anti-PII: nenhum dado é persistido além do par lat,lng no cache local). Sem chaves de API; uma requisição leve por consulta nova.
- Mitigações obrigatórias (parte da decisão):
  - (a) **Escopo restrito:** fetch HTTP SÓ no caminho de resolução de endereço da barra de busca. NADA de rede na carga/interatividade do dashboard nem no mapa (Blocos 4–6 e basemap seguem como estão; DEC-004 inalterada).
  - (b) **Cache local** das resoluções em `data/cache/geocode/` (gitignored, coberto pelo padrão `data/cache/` do `.gitignore`); minimiza requisições repetidas.
  - (c) **Fallback offline gracioso:** sem rede/falha/timeout → exibe link clicável do Maps (`build_search_url`, função PURA) + instrução para copiar/colar a coordenada, sem exceção. Default seguro sem rede em CI/teste, coberto por teste com mock (a suíte NUNCA bate na rede real).
  - (d) **Timeout curto** (6 s) + `try/except` amplo na função e no chamador; a interatividade offline do dashboard NUNCA quebra se a rede faltar.
  - (e) **I/O isolado** no helper de `maps_geocoder.py` (camada `api`, `urllib` puro, sem Selenium); o import no dashboard é lazy e a rede só ocorre na chamada de busca por endereço.
  - (f) **Nota anti-PII + atribuição** registradas nesta DEC e no aviso do campo (mitigação (c)/(f)).
- Pesos/fórmula/artefatos do M1: **INALTERADOS** (`renda=0.40`/`pop=0.60`, `score_priorizacao`, `hex_score_estrutural`, carteira, plano, artefatos oficiais). Camada de visualização/consumo (§5 guardrail permanente).
- Parâmetros canônicos do §3: INALTERADOS (nenhum parâmetro de score; só adição do helper de rede e do diretório de cache de geocode).
- Referências: `tasks/backlog.md` (BLK-UI-08); `context/handoff.md` (Planner/Builder); `src/motor_expansao/api/maps_geocoder.py` (`resolve_endereco_http`); `src/motor_expansao/dashboard/pages.py` (`render_coord_search_sidebar`); CLAUDE.md §2/§4/§5; DEC-004 (precedente de desvio do §2 restrito a um caminho específico).
- **Emenda 2026-06-17 (BLK-UI-08-FU1, APROVADA por Vinicius): provedor de geocoding = Nominatim/OpenStreetMap, não Google.** Na validação visual o fetch `urllib` puro contra o Google Maps NÃO resolvia coordenada (a página do Maps é renderizada por JS; sem navegador a URL final não traz o pino `!3d/!4d` nem `@lat,lng`), então a Alternativa B só caía no fallback. Correção: `resolve_endereco_http` passa a fazer um GET ao **Nominatim** (`https://nominatim.openstreetmap.org/search?format=jsonv2&limit=1&countrycodes=br&q=...`) e lê `lat/lon` do JSON — HTTP puro `urllib`, sem navegador, funciona de fato. Consequências: (i) o endereço digitado passa a ser enviado ao **OpenStreetMap/Nominatim** (não ao Google) — nota anti-PII e atribuição **© OpenStreetMap contributors** atualizadas; (ii) enviamos **User-Agent identificável** (`motor-expansao-ultra/...`) conforme a [Nominatim Usage Policy](https://operations.osmfoundation.org/policies/nominatim/) (máx. 1 req/s, sem uso em massa) — uso sob demanda do dashboard fica folgado e o **cache local `data/cache/geocode/`** (mitigação (b), inalterada) cobre a exigência de caching. As demais mitigações (a)/(c)/(d)/(e)/(f) seguem VIGENTES; o fallback offline (c) ainda usa o link clicável do Google Maps (`build_search_url`, função pura) só como atalho manual. READ-ONLY sobre o M1 inalterado.
- **Emenda 2026-06-19 (BLK-UI-09, APROVADA por Vinicius — Opção B): link do Google Maps como 3º formato da busca, incluindo seguir o redirect de LINKS CURTOS via rede.** A barra de busca (`render_coord_search_sidebar`) passa a aceitar TRÊS formatos: coordenada `lat,lng` (numérico, INTOCADO) → **link do Maps** (NOVO) → endereço (Nominatim, INTOCADO). URLs longas (`!3d/!4d` ou `@lat,lng`) são resolvidas **offline por regex pura** (`extract_any_coord`, sem rede). Para **links curtos** (`maps.app.goo.gl`, `goo.gl/maps`) — que não trazem a coordenada na string — o humano aprovou seguir o **redirect HTTP** para obter a URL longa final e então extrair a coordenada: novo helper `resolve_short_link(url, *, timeout=6.0) -> str | None` em `src/motor_expansao/api/maps_geocoder.py` (camada `api`, `urllib.request` puro, lê `resp.geturl()` após os redirects), import lazy no dashboard. Este é um **3º sub-caminho de rede** que ESTENDE a DEC-010 (antes: rede só no caminho de endereço). Mitigações herdadas da DEC-010, todas VIGENTES e obrigatórias: (a) escopo restrito — rede SÓ neste sub-caminho da busca, nada na carga/interatividade do dashboard nem nos Blocos 4–6/basemap; (c) fallback gracioso — sem rede/falha/timeout → mensagem clara pedindo a URL longa ou a coordenada, sem exceção (a suíte NUNCA bate na rede real, testada com mock de `urllib`); (d) timeout curto (6 s) + `try/except` amplo; (e) I/O isolado em `maps_geocoder.py` + import lazy; (f) nota anti-PII — a URL curta é enviada ao Google **só** para seguir o redirect; nada é persistido além do par lat,lng. O resultado de qualquer caminho de link é validado contra o bounding box do Brasil (`_validate_brazil_bbox`); fora do Brasil → `None` + mensagem. Pesos/fórmula/artefatos do M1: **INALTERADOS**; parâmetros canônicos do §3: INALTERADOS (só helper de rede + roteamento de UI). READ-ONLY sobre o M1.
