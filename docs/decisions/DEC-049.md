### DEC-049 — telegram-bot ganha `MOTOR_DATA_DIR` + bind do `perfil.json`: fecha a divergência com a `api` que causava crash loop em produção

- ID: DEC-049 | Data: 2026-09-08 | Criticidade: Crítica (toca `docker-compose.prod.yml`, núcleo protegido de deploy)
- Status: APROVADA por Felipe Silva em 2026-09-08 (fix emergencial já aplicado na VPS antes deste registro)
- Decisão: o serviço `telegram-bot` do `docker-compose.prod.yml` passa a ter a mesma `MOTOR_DATA_DIR: "/app/data"` e o mesmo bind `data/perfil.json:/app/data/perfil.json:ro` que o serviço `api` já tinha (Bloco A/DEC-047). Sem código Python alterado — só configuração de deploy.

---

#### O defeito

O Bloco A/DEC-047 deu à `api` `MOTOR_DATA_DIR` porque `motor_expansao.perfil.resolver_perfil()`
passou a rodar **no import** de `api/coord.py` — sem a env, o loader cai no ramo "BR embarcado",
que resolve o caminho do `perfil.json` por `__file__` para dentro do `site-packages`, caminho que
nunca existe sob instalação não-editável (`Dockerfile.api`). O fix foi aplicado só ao bloco `api`
do compose; o `telegram-bot` roda a **mesma imagem** e importa o **mesmo módulo**, mas ficou de
fora — divergência entre os dois blocos, nunca exercitada porque a API não tinha sido republicada
desde o Bloco A até este deploy.

#### O sintoma medido

2026-09-08, primeiro deploy da API desde o Bloco A (republish manual do main atual para trazer o
DEC-046 — união das 3 fontes de oferta no Relatório Pontual — ao ar): `motor_expansao_telegram_bot`
entrou em crash loop imediatamente após o restart, com:

```
motor_expansao.perfil.PerfilInvalidoError: perfil.json ausente em
/usr/local/lib/python3.11/data/perfis/BR/perfil.json
```

#### O fix

Copiados ao bloco `telegram-bot`:
- `MOTOR_DATA_DIR: "/app/data"` (environment)
- `- /opt/motor-expansao/data/perfil.json:/app/data/perfil.json:ro` (volumes)

Aplicado emergencialmente na VPS via `docker-compose.prod.yml` editado in loco (backup
`docker-compose.prod.yml.bak-20260908-botperfil`), bot recriado e confirmado estável. Este DEC +
PR fecham a divergência na fonte, para que o próximo `git pull` + deploy na VPS já traga o fix
sem depender do hotfix manual.

READ-ONLY sobre o M1. Sem mudança de código Python — só o `docker-compose.prod.yml`.
