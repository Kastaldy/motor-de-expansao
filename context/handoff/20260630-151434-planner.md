## Plano técnico

### 1. Definição do alvo, features e tratamento de zeros (`backtest_tp05.py`)
1.1. **Alvo (modelagem principal):** `y = log1p(alunos_parceiras)` sobre o subconjunto
   `alunos_parceiras > 0` (n≈5.341). Log porque a cauda é longa (max 14.332) — mesma escolha de
   `aderencia.py` (modela em log). `log1p` (não `log`) por robustez, mas como o subset já é > 0 o
   efeito é equivalente a `log`. **DECISÃO DE MODELAGEM A1** (ver Alerta): modelar só os hexes com
   parceiras > 0 (regressão de magnitude, condicional à presença), NÃO os 16.575 (a maioria 0
   tornaria o alvo dominado por zeros e o R² seria gameado pela separação 0/não-0, não pela
   magnitude). Reportar o N descartado (10.234 hexes com `alunos_parceiras == 0`).
1.2. **Feature set principal (DECISÃO DE MODELAGEM A2):**
   `X = [log1p(membros), log1p(dist_concorrente_lc_min_m), n_concorrente_lc]`.
   - `membros` em log1p (mesma transformação do alvo; relação tipo potência).
   - `dist_concorrente_lc_min_m` em log1p (escala enorme: até 1,7 M m).
   - `n_concorrente_lc` cru (contagem 0–7).
1.3. **`n_acad_parceiras` é EXCLUÍDO do feature set principal** (DECISÃO DE MODELAGEM A3): rho +0,94
   no universo / +0,76 no subset com o alvo — é a contagem de parceiras das quais `alunos_parceiras`
   é a SOMA → relação quase mecânica/circular (mais parceiras ⇒ mais alunos por construção). Incluí-lo
   produziria GO espúrio por vazamento estrutural. Reportar como confound e rodar **um modelo
   SECUNDÁRIO rotulado "auditoria — vazamento estrutural"** com ele, só para evidenciar o salto de R²
   atribuível à circularidade (NÃO usado no veredito).
1.4. **`membros_gt5km_concorrente_lc` é EXCLUÍDO do principal** (subconjunto de `membros`; colinear).
   Pode entrar num modelo secundário de sensibilidade se o humano pedir.
1.5. Limpeza: dropar linhas com NaN/inf em qualquer feature ou alvo; registrar `n_descartado_*`.

### 2. Estratégia de validação honesta (k-fold repetido vs baseline)
2.1. **K-fold repetido**: `RepeatedKFold(n_splits=5, n_repeats=5, random_state=42)` (sklearn).
   Justificativa do N: 5.341 ≫ 30 → fold de treino ~4.273 obs (estável); LOO seria 5.341 fits sem
   ganho estatístico. Reusar `Ridge` (mesma família regularizada de `aderencia.py`) com varredura do
   **mesmo `ALPHA_GRID = (0.01, 0.1, 1.0, 10.0, 100.0)`** importado de `aderencia.py`, selecionando
   alpha por **menor RMSE médio out-of-fold** (mesma regra de `aderencia.py`).
2.2. **R²_oof (out-of-fold) é a métrica-âncora**: para cada fold, treina nos 4/5, prediz no 1/5
   retido; concatena predições oof; `R²_oof = _r2(y, y_pred_oof)` reusando `_r2` de `backtest_dim.py`
   (R² já é definido lá vs a média ⇒ é a comparação contra o baseline). Repetir 5× e reportar a MÉDIA
   e o desvio entre repetições.
2.3. **Piso de N e fallback (DECISÃO DE MODELAGEM A4):** se após limpeza `n < 200`, usar
   `RepeatedKFold(n_splits=10, ...)`; se `n < 30`, marcar `flag_extrapolacao_padrao_global = True`
   e degradar para LOO (reusando `_r2_loo_para_alpha` de `aderencia.py`). Com o N atual (~5,3 mil)
   o caminho normal é k=5×5. (O fallback existe só para robustez/fixture sintética.)

### 3. Baseline da média (métrica-âncora explícita)
3.1. Baseline = predizer a **média de `y` do treino de cada fold** (não a média global). `R²_oof`
   já mede modelo vs essa referência (R² < 0 ⇒ pior que o chute da média). Reportar também
   `rmse_oof_modelo` vs `rmse_oof_baseline` (baseline oof = média do treino do fold) lado a lado,
   no espaço log E no espaço de alunos (back-transform `expm1` das predições oof) para leitura
   operacional — espelhando os dois espaços de `aderencia.py`.

### 4. Intervalo de confiança + flag de extrapolação por ponto
4.1. **IC do R²_oof por bootstrap (DECISÃO DE MODELAGEM A5):** `N_BOOTSTRAP = 500` (≥500 exigido nos
   critérios de aceite) reamostragens com reposição dos pares `(y, y_pred_oof)`; IC95 = percentis
   [2,5; 97,5] do R²_oof reamostrado; seed fixa 42. (Alternativa permitida pelos critérios: ±RMSE_oof
   analítico — o plano adota bootstrap por dar IC do próprio R², mais informativo.)
4.2. **Flag de extrapolação por ponto** (envelope min-max das features de treino, padrão de
   `AderenciaModel.flag_extrapolacao`): para cada hex, `True` se qualquer feature cair fora do
   [min, max] observado no treino. Reportar `% de pontos extrapolados`. Como aqui treino e teste vêm
   do mesmo dump, o esperado é ~0%; o campo existe para o contrato honesto e para reuso futuro.
4.3. `flag_extrapolacao_padrao_global = (n_treino < 30)` (mesma heurística de `aderencia.py`).

### 5. Critério numérico de GO/NO-GO
5.1. **Herdar `LIMIAR_R2_GO = 0.05`** de `aderencia.py` (importar; NÃO redefinir).
   **GO** se `R²_oof > 0,05` E `IC95_inferior(R²_oof) > 0` (sinal materialmente acima da média e IC
   não cruza zero — espelha a regra "IC sem cruzar zero" da DEC-001/DEC-008). Caso contrário **NO-GO**.
   NO-GO é resultado VÁLIDO e esperado (DEC-008).

### 6. R² in-sample — apenas auditoria
6.1. Pode-se computar `r2_insample = _r2(y, modelo_full.predict(X))` SOMENTE como campo rotulado
   literalmente **"apenas auditoria — NÃO usar como desempenho"** (string fixa, testada por substring),
   nunca no veredito (DEC-008). Espelha `r2_insample_log` de `aderencia.py`.
