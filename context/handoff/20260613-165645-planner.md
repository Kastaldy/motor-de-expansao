## Decisões tomadas (D1–D8)

### D1 — Alvo do modelo
- **Alvo = `y = log(pagantes_steady_state)`** (corrige a endogeneidade: log(pop) sai do denominador).
- **Filtros de limpeza** (linha removida se QUALQUER condição):
  - `pagantes_steady_state` NaN ou ≤ 0
  - `pop_captacao` NaN ou ≤ 0
  - `renda_per_capita_captacao` NaN ou ≤ 0
  - `n_setores_captacao == 0` ou NaN — **somente quando a coluna existir** (opcional, flag de catchment vazio)
- **NÃO filtrar por penetração > 1.0.** Penetração deixou de ser o alvo; o outlier de penetração=1.10
  do spike (≈4057 pagantes) **PERMANECE na amostra** — 4057 não é outlier em pagantes absolutos
  (q75=1801, max observado=4057 é o próprio teto plausível da distribuição). Removê-lo seria descartar
  sinal legítimo. **Decisão: manter** (não há clip de pagantes-absolutos neste bloco).
- N efetivo esperado: **53** (54 − 1 unidade com NaN de pop/renda). Difere dos 52 do spike porque
  o filtro de penetração>1.0 foi removido.

### D2 — Features e transformações
- **Feature 1: `log(pop_captacao)`** — exógena ao novo alvo (não está mais no denominador).
- **Feature 2: `log(renda_per_capita_captacao)`** — exógena ao novo alvo.
- **`meses_desde_inauguracao`: EXCLUIR como feature.** Justificativa: (i) todas as 54 unidades já são
  maduras (`flag_madura`=100% True, 15–65 meses), então o alvo já é steady-state — controlar maturação
  é redundante; (ii) o BO (R3) adverte que cria **viés preditivo**: ao prever um hex NOVO não sabemos
  quantos meses ele terá, e atribuir um valor de meses arbitrário contamina a predição com uma feature
  não-disponível no momento da decisão. O modelo final deve usar SÓ features que existem para um hex
  candidato. Mantemos a parcimônia (2 features, N=53 → ~26 obs/feature, já no limite para LOO honesto).
- **Normalização: `StandardScaler`** (manter do spike — z-score). Motivo: Ridge penaliza coeficientes
  proporcionalmente à escala; com 2 features em log já de magnitude similar, StandardScaler dá o
  regularização mais estável e comparável entre alphas. MinMaxScaler é sensível a min/max (com N pequeno
  e possíveis caudas, menos robusto). **IMPORTANTE:** o scaler deve ser **ajustado DENTRO de cada fold
  do LOO** (fit no train, transform no test) para não vazar informação do ponto de teste — ver D3.
  - Nota de implementação: o spike NÃO usava scaler explícito (passava log_pop/log_renda crus ao Ridge).
    Como ambas as features são log e de escala parecida, o Builder PODE manter sem scaler (mais simples,
    sem risco de vazamento) OU usar `StandardScaler` por fold. **Recomendação do Planner: manter SEM
    scaler** (features log cruas), igual ao spike — é o caminho mais simples e auditável, e elimina
    qualquer risco de vazamento de escala no LOO. Documentar essa escolha no relatório.

### D3 — Grid de regularização e critério de GO/NO-GO
- **`ALPHA_GRID = (0.01, 0.1, 1.0, 10.0, 100.0)`** (manter do spike).
- **Seleção de alpha por MENOR `rmse_loo_log`** (não por maior R²_LOO). Mais robusto a instabilidade de
  R² com N pequeno. (R²_LOO e RMSE_LOO são monotonicamente relacionados quando ss_tot é fixo, então o
  alpha escolhido coincide; mas reportar RMSE como critério deixa o código mais honesto e estável.)
- **`R2_LOO_GO_LIMIAR = LIMIAR_R2_GO = 0.05`** (manter do spike).
- **Calcular R²_LOO em DOIS espaços:**
  - (a) **espaço log**: `r2_loo_log` sobre `y = log(pagantes)` — **MÉTRICA PRINCIPAL DO GATE**.
  - (b) **espaço de pagantes**: `r2_loo_pagantes` — exponenciar as predições LOO (`exp(y_pred_loo)`) e
    comparar contra `pagantes` reais; `ss_tot` no espaço de pagantes usa a média de `pagantes` (não de log).
    Reportado para interpretabilidade, **não decide o gate**.
- **Critério de GO:** `veredito = "GO" if r2_loo_log > LIMIAR_R2_GO else "NO-GO"` (consistente com spec §7;
  o gate é no espaço log, espaço de modelagem). Esperado: **NO-GO** (r2_loo_log ≈ −0.028).
- **LOO por fold (anti-vazamento):** para cada alpha, rodar `LeaveOneOut`, treinar Ridge no fold de treino,
  prever o ponto deixado de fora, acumular `y_pred_loo`. R² e RMSE calculados sobre o vetor `y_pred_loo`
  completo. (Reutilizar `_r2_loo_para_alpha` do spike, que já faz isso — apenas estender para retornar
  o vetor `y_pred_loo` e/ou também as predições no espaço de pagantes.)

### D4 — Saída de `prever_aderencia`
- Assinatura mantém o nome, **muda a UNIDADE de saída**: retorna `(pagantes, ic_lower, ic_upper)` em
  **alunos absolutos** (inteiros conceituais, mas `float`), NÃO fração de penetração.
- **Cálculo:** `log_pagantes_hat = intercepto_log + coef_log_pop*log(pop) + coef_log_renda*log(renda)`;
  `pagantes = exp(log_pagantes_hat)`.
- **Clamp:** `min = 1.0` aluno (nunca negativo/zero); `max = pop_captacao` (sanidade — não pode haver mais
  pagantes que população no catchment). Aplicar o mesmo clamp a `ic_lower`/`ic_upper`.
- **IC:** propagar incerteza via `rmse_loo_log` (erro médio honesto no espaço de modelagem), back-transformado:
  - `ic_lower = clamp(exp(log_pagantes_hat − rmse_loo_log))`
  - `ic_upper = clamp(exp(log_pagantes_hat + rmse_loo_log))`
  - Garantir ordem pós-clamp: `ic_lower = min(ic_lower, pagantes)`, `ic_upper = max(ic_upper, pagantes)`.
  - Justificativa: ±1·RMSE_LOO é a banda honesta de erro fora-da-amostra; é a mesma abordagem do spike,
    apenas no espaço de pagantes. NÃO usar perturbação de alpha (instável, sem ganho com N pequeno).
- **Entrada inválida:** `pop ≤ 0` ou `renda ≤ 0` → retorna `(1.0, 1.0, 1.0)` (piso de 1 aluno), sem exceção.
- **Alias `aderencia_calibrada = prever_aderencia`** mantido.

### D5 — Fixture nova (anti-circular) — OBRIGATÓRIO
A fixture de sinal DEVE gerar `log(pagantes)` **diretamente**, sem passar por penetração. Código exato:

```python
@pytest.fixture
def df_log_sinal() -> pd.DataFrame:
    """30 unidades onde log(pagantes) = b0 + b1*log(pop) + b2*log(renda) + ruido.

    Gera log(pagantes) DIRETAMENTE (anti-circular): nunca cria coluna de penetracao
    nem multiplica por pop. b1 positivo e moderado -> sinal real calibravel (GO).
    """
    rng = np.random.default_rng(42)
    pop = np.geomspace(2000.0, 130000.0, 30)
    renda = rng.permutation(np.geomspace(600.0, 16000.0, 30))
    log_pop = np.log(pop)
    log_renda = np.log(renda)
    b0, b1, b2 = -1.0, 0.8, 0.1
    log_pagantes = b0 + b1 * log_pop + b2 * log_renda + rng.normal(0, 0.30, 30)
    pagantes = np.exp(log_pagantes)
    return pd.DataFrame(
        {
            "pop_captacao": pop,
            "renda_per_capita_captacao": renda,
            "pagantes_steady_state": pagantes,
            "n_setores_captacao": rng.integers(3, 40, 30),
        }
    )
```

**ARMADILHA (R5 do BO):** NÃO reaproveitar o `df_log_sinal` antigo do spike — ele fazia
`log_penet = b0 + b1*log_pop + eps; pagantes = exp(log_penet)*pop`, o que dá
`log(pagantes) = b0 + b1*log_pop + eps + log_pop = b0 + (b1+1)*log_pop + eps` →
ainda perfeitamente correlacionado com `log_pop` por construção. A fixture acima evita isso
gerando `log_pagantes` direto. Com `b1=0.8` e `sigma=0.30` o sinal é forte mas com ruído
realista → GO esperado (R²_LOO_log > 0.05), sem ser circular trivial (sigma não-desprezível).
