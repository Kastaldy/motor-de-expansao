## O que foi feito

Implementado o módulo `aferir_overlap_nao_abra.py` que cruza as bases reais de
estabelecimentos do NAO_ABRA/ (01_SmartFit.xlsx e 03_Competidores.xlsx) contra
`data/staging/concorrentes_densos.parquet`, calculando recall e overlap por rede,
e gerando relatório em `data/analysis/relatorio_overlap_nao_abra.md` (gitignored).

**Resultados do relatório real (dados reais, 2026-07-07):**
- Recall Smart Fit: **98.0%** (733 de 748 hexes únicos do 01_SmartFit encontrados na base densa)
- Recall global 03_Competidores: **70.4%** (5.109 de 7.253 pares) — subestimado sistematicamente
  pelo viés de coords com 1-2 decimais (~10 km de precisão → hex errado)
- SKYFIT: 339 linhas classificadas como `independente` (gap de token documentado; base densa
  tem skyfit via fonte `unidades`)
- Veredito: base densa **suficiente para o modelo Huff**

**Estrutura do módulo:**
- `_to_hex`: converte lat/lng para H3 res-7 com try/except
- `_ler_smartfit`: lê xlsx, deriva hex, dropa PII imediatamente
- `_ler_competidores`: lê xlsx, deriva hex + rede via `classificar_rede`, conta skyfit não
  reconhecidos antes do drop-PII, retorna tupla `(df, n_skyfit_nao_reconhecido)`
- `calcular_metricas_smartfit`: recall, intersecção, ausentes/excedentes
- `calcular_metricas_competidores`: recall global, tabela por rede (excl. `independente`)
- `_assert_sem_pii_relatorio`: verifica headers de tabela markdown anti-PII
- `gerar_relatorio`: markdown PT-BR com disclaimers, tabelas, caveats, recomendação
- `executar`: orquestrador que lê parquet denso READ-ONLY e chama as demais funções

  o recall sintético para ≥ 0.67 (2/3). Todos os 12 passam depois da correção.
