## Sumário executivo do diagnóstico
O custo Python de render do mapa NÃO está no downsample (F1: 15–123 ms) nem na materialização de colunas (F2: 10–34 ms), juntos < 6% do builder. O gargalo é a serialização pydeck `deck.to_json()` (F3: 0,6–1,0 s) que produz um payload JSON de ~21–24 MB por mapa, linear em N (~1,21 KB/hex). Desse JSON, ~65% (15,7 MB em 20k hexes) são as 14 strings de tooltip por hexágono; só ~8,5% é geometria (hex_id+cores).

## Hipótese principal e melhor opção
Causa-raiz = serialização `to_json` + payload gordo dominado por tooltips (Hipóteses B+C). Melhor opção = tooltip enxuto no payload (corta ~65% do JSON sem reduzir nº de hexes), depois baixar o cap (18k→12k, quick win ∝ N) e memoizar o layer por hash de params. Tiles vetoriais/MVT tem maior teto mas é reescrita de alto risco (deixar como fase separada com gate humano). `@st.fragment` já está aplicado (pages.py:4099).
