## Insight matemático que define o desenho do parâmetro de escala
A largura final embutida no PDF (`draw_w`) em `_draw_maps_grid`/`_competitors_page` é
`min(cw/img_w, ch/img_h) * img_w`, onde `cw`/`ch` são constantes FIXAS da página (`_map_grid_cells`
para o slide 2; `max_w=560,max_h=430` para o slide 3) — **independentes** de `img_w`/`img_h`.
Quando a proporção do canvas é preservada, `draw_w` colapsa exatamente em `cw`, **qualquer que
seja o tamanho do canvas**. Consequência: escalar canvas E fontes E coordenadas pelo MESMO fator
(a assinatura ingênua sugerida no prompt do orquestrador) é **matematicamente um no-op para o
tamanho físico do texto no PDF** — só melhora nitidez (mais pixels por glifo antes do downsample),
não resolve "fonte pequena". Prova: `pt_efetivo = font_px * (cw/img_w)`; se `font_px` e `img_w`
escalam pelo mesmo fator `S`, o `S` cancela. **Para aumentar `pt_efetivo`, a fonte precisa crescer
MAIS RÁPIDO que a largura do canvas** (razão `font_px/img_w` tem que aumentar). Por isso a
abordagem recomendada abaixo é **fonte-only** (não mexe em `width`/`height` do canvas para
resolver "tamanho"; canvas maior é alavanca SEPARADA, opcional, só para nitidez do mapa/streets).
