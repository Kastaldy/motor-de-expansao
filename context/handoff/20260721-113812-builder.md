## Desvios em relação ao plano (3, todos registrados; nenhum enfraquece asserção)

1. **Pixel-sonda da sombra no teste 4.1.1.** O plano pedia `tile.getpixel((29, 29))` com
   `0 < alpha < 255`; medido, esse vértice é `(0, 0, 0, 0)` porque `radius=3` **arredonda o canto**.
   Usei `(29, 15)` = `(size - 1, size // 2)` (meio do lado direito), que devolve exatamente
   `(0, 0, 0, 60)` -> `0 < alpha < 255` ✅. A asserção continua provando o mesmo (sombra presente,
   translúcida), num pixel que existe.
2. **`_MINIMAL_PNG` não serve para provar o ramo "tem logo".** O plano previa reusá-lo no teste
   4.1.3; medido, ele é um stream **quebrado** — `Image.open(...).convert("RGBA")` levanta
   `OSError: broken data stream when reading image file`, então `_render_square_logo_tile` cai no
   `except` e vai para o **fallback de sigla** (verificado: o tile ficava com 479 px de
   `(200, 0, 30)`), o que faria a asserção "cor de marca ausente" falhar. Adicionei o helper local
   `_valid_png()` (gera um PNG real com Pillow) e o teste ficou **mais forte** que o planejado:
   além de `(200,0,30,255)` ausente e branco presente, exige a **cor da própria logo**
   `(0,128,255,255)` no tile. `_MINIMAL_PNG` e os testes que o usam **não foram tocados**.
3. **`zip(..., strict=True)`** no teste diferencial (regra `B905` do ruff), com
   `zip(uniq[:-1], uniq[1:], strict=True)` para os comprimentos casarem.

**Nenhum limite numérico precisou do grau de liberdade de ±25%** — todos os valores medidos caíram
dentro das faixas do plano na primeira tentativa.
