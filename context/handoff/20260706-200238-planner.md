### 4. Normalização dos eixos para 0–100 (percentil nacional) — função `_normalizar_eixos`
4.1. Objetivo do critério de aceite #3: os 3 eixos na MESMA escala 0–100 via percentil nacional. Usar `scipy.stats.rankdata` ou `pd.Series.rank(pct=True)*100` sobre o df **pós-gate** (percentil dentro do conjunto viável — coerente com "nacional" restrito ao universo modelado; documentar essa escolha no relatório).
4.2. Eixos `sociodemo` (`score_priorizacao`) e `mercado` (`score_oportunidade_residual`): já são 0–100, mas normalizar por percentil garante comparabilidade e trata caudas. Criar colunas `eixo_sociodemo_norm`, `eixo_mercado_norm`.
4.3. Eixo `disputa` — **INVERTER o share** ANTES de normalizar: `disputa_bruta = 1.0 - share_captura_huff` (mais share = MENOS oportunidade → 1−share alinha "mais disputa vencível" com o sinal positivo; coerente com o rho=−0,581 medido pelo BO). Depois normalizar por percentil → `eixo_disputa_norm`.
4.4. **Degradação graciosa do eixo disputa** (critério #6): onde `share_captura_huff == 1.0` (sem concorrentes na janela = monopólio local, ~72% do join), criar `flag_huff_disponivel = share_captura_huff < 1.0`. O eixo disputa segue no frame (1−1=0 → percentil baixo, informa "sem oportunidade de disputa aqui"), mas REPORTAR `pct_huff_disponivel` e rodar uma sub-análise separada (passo 7) só nos hexes com `flag_huff_disponivel==True`.
4.5. NÃO tocar `membros` (é o ALVO; não normalizar).

### 6. Modelos testados out-of-fold (função-núcleo `_avaliar_modelo`)
Cada modelo produz `(r2_oof, ic95_r2, rho_oof, ic95_rho, r2_insample, y_pred_oof, alpha)`. Reusar `_selecionar_alpha_e_oof` (já faz seleção de alpha + oof), `_ic_bootstrap_r2`, `_ic_bootstrap_rho`, `_rho_oof`; `r2_insample` via `Ridge(alpha).fit(X,y).predict(X)` + `_r2` (SÓ auditoria, rótulo `_ROTULO_INSAMPLE`).
Assinatura sugerida: `_avaliar_modelo(X: np.ndarray, y: np.ndarray, metodo: str) -> ModeloOOF` (dataclass leve).
Limpeza: `finito = np.isfinite(X).all(axis=1) & np.isfinite(y)` ANTES; N efetivo por modelo pode variar (censitário tem NaN em ~4%). Reportar N por modelo.

Modelos exigidos (critério #2):
6.1. **Baseline**: média de `y` no treino de cada fold. JÁ é a âncora do R² (R²_oof vs média = 0 por construção). Registrar `R²_oof_baseline = 0.0` e `RMSE_oof_baseline` (via `_selecionar_alpha_e_oof` que retorna `y_pred_baseline_oof`). Não é um modelo Ridge — é o referencial.
6.2. **Eixo 1 isolado — sociodemo**: `X = [eixo_sociodemo_norm]`.
6.3. **Eixo 2 isolado — mercado**: `X = [eixo_mercado_norm]`.
6.4. **Eixo 3 isolado — disputa**: `X = [eixo_disputa_norm]` (1−share normalizado). Rodar em DUAS variantes: (a) sobre TODO o df pós-gate (com monopólios); (b) sub-análise só onde `flag_huff_disponivel` (passo 7).
6.5. **Eixo 2b isolado — censitário (auditoria)**: `X = [score_setor_2022_calibrado_norm]`, SE a coluna existir e tiver variância. FORA do composto; só reproduz rho +0,234 do BO. Rotular "auditoria".
6.6. **Melhor eixo isolado**: `argmax(R²_oof)` entre 6.2/6.3/6.4a (os 3 eixos DO composto — censitário NÃO conta para o benchmark do composto, pois não entra nele). Guardar nome + métricas + `y_pred_oof` do melhor.
6.7. **Score composto**: combinação linear Ridge dos 3 eixos: `X = [eixo_sociodemo_norm, eixo_mercado_norm, eixo_disputa_norm]`. Alpha por RMSE_oof (Ridge leve trata multicolinearidade — risco 5 do BO). Guardar coeficientes finais (auditoria de pesos aprendidos). **Degradação (critério #6)**: onde `share==1.0`, o eixo disputa entra como 0 normalizado (não NaN) → o composto NÃO perde linhas; documentar que nesses hexes o composto opera efetivamente com 2 eixos ativos. NÃO criar um segundo composto de 2 eixos separado (evita explosão de modelos) — a degradação é via o valor 0 do eixo, documentada.
6.8. **Composto pesos-iguais (auditoria)**: `X = [(sociodemo+mercado+disputa)/3]` como 1 feature (média simples dos 3 eixos normalizados), validado oof. Reportado AO LADO do composto-Ridge para transparência (o backlog cita "Ridge leve ou pesos iguais"; entregar os dois — Ridge é o principal, pesos-iguais é auditoria).
6.9. **Matriz (baseline humano)**: NÃO é modelo. É o default operacional = os 3 eixos LIDOS separados. Representá-la como a TABELA dos 3 R²_oof isolados + os rhos. No veredito, "vencer a matriz" ≡ o composto vencer o `melhor eixo isolado` (6.6) materialmente (risco 4 do BO).

### 7. Sub-análise dos competitivos (função `_subanalise_huff_disponivel`)

Reportar `n_competitivos`, `pct_competitivos`, e o R²_oof do eixo disputa/composto restrito. Nota: o eixo Huff é informativo APENAS onde há concorrentes na janela (risco 1 do BO).

### 8. Correlações bivariadas + cruzadas (ANTES do modelo) — função `correlacoes`
8.1. Spearman de cada eixo bruto (não invertido para leitura) vs `membros`: `share_captura_huff`, `score_priorizacao`, `score_oportunidade_residual`, `score_setor_2022_calibrado`. Deve reproduzir os rhos do BO (−0,581 / +0,490 / +0,517 / +0,234) — sanity check no relatório.
8.2. Correlações CRUZADAS entre eixos normalizados (risco 5 do BO — multicolinearidade): reportar rho(mercado_norm, disputa_norm), rho(sociodemo_norm, mercado_norm), rho(sociodemo_norm, disputa_norm). Documentar ANTES do composto.

### 9. Veredito GO/NO-GO honesto (função `_decidir_veredito`) — critério #7
9.1. Calcular `r2_melhor_eixo = max(R²_oof de sociodemo/mercado/disputa-full)`.
9.2. `ganho_material = R²_oof_composto - r2_melhor_eixo`.
9.3. `redundante = pearson(y_pred_oof_composto, y_pred_oof_melhor_eixo) >= LIMIAR_REDUNDANCIA`.
9.4. **Veredito COMPOSTO = GO** SE e SÓ SE TODAS:
   - `R²_oof_composto > LIMIAR_R2_GO (0.05)` E `IC95_inf(R²_composto) > 0` (bate o baseline da média com confiança), E
   - `ganho_material > LIMIAR_GANHO_MATERIAL (0.01)` (vence o melhor eixo isolado materialmente), E
   - `NOT redundante` (a combinação não é só uma cópia do melhor eixo).
9.5. Caso contrário → **Veredito = NO-GO (usar a MATRIZ)** — os 3 eixos separados como default operacional. NO-GO é resultado VÁLIDO (DEC-008). Registrar o MOTIVO do NO-GO (qual condição falhou: não bateu baseline / não venceu melhor eixo / redundante).
9.6. NÃO usar R² in-sample em NENHUMA condição do veredito (só campo de auditoria rotulado; DEC-008).

1. **share=1.0 em ~72% do join (monopólio local)**: tratado no passo 4.3/4.4/7 — `flag_huff_disponivel`, inversão `1−share`, sub-análise separada dos competitivos, nota de que o Huff é informativo só onde há concorrentes. O composto usa o eixo como 0 nesses hexes (2 eixos efetivos), documentado.

3. **N pós-gate cai abaixo dos pisos**: `_metodo_validacao(n)` importado já degrada k=5→k=10→LOO automaticamente; passo 3.4 garante N correto. `flag_extrapolacao_padrao_global` reportada.
4. **"Vencer a matriz" mal definido**: operacionalizado no passo 9 — matriz = melhor eixo isolado; composto GO só com ganho material (>0.01) sobre ele E não redundante (<0.95) E bate baseline (IC>0). Default = matriz.
5. **Multicolinearidade dos eixos** (rho residual×share ≈ −0,42 no metrô): Ridge trata; correlações cruzadas reportadas ANTES do modelo (passo 8.2); teste de redundância (passo 9.3) evita GO espúrio quando o composto só copia um eixo.
6. **Vazamento do alvo**: os eixos são todos preditores geométricos/de score PUROS; `membros` só entra como `y`. Teste 12.8 blinda.
