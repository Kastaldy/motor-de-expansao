## 1. Fórmula do M2 e pesos propostos

### 1.1. Os dois eixos (colunas REAIS do parquet, confirmadas por inspeção)
O M2 pondera **captação** (o quanto o território atrai/comporta demanda) + **retenção territorial** (o quanto a demanda permanece). Ambos os eixos são derivados de features **territoriais** (por hexágono) — NUNCA de atributos de unidade (ticket, N_ALUNOS, maturidade).

- **Eixo CAPTAÇÃO** = `score_priorizacao` (0–100). É o composto M1 (renda 0.40 + pop 0.60) — já é, por construção, o proxy de captação/demanda da camada executiva. LIDO, nunca recalculado (DEC-001). É a mesma coluna que carrega o sinal de retenção no LTV-03 — ver nota de colinearidade em §Riscos.
- **Eixo RETENÇÃO territorial** = **modelo de retenção calibrado fora-de-fold** que usa como preditores territoriais **`score_priorizacao`** (carregador; +0.391 vs LTV) e, como candidatos secundários testados na validação, `renda_per_capita`, `densidade_pop_setor_hab_km2`, `score_setor_2022_calibrado`, `n_concorrentes_mapeados_1km`. A saída do eixo é a **retenção territorial prevista** re-escalada para 0–100 (percentil nacional sobre o universo de hexes onde as features existem).
  - Alvo de treino do eixo (por unidade, agregado — regra canônica do epic): `LTV_PROSPECTIVO_12M_MEDIANO` (eixo ranking, N=56) — o par mais forte e maturidade-robusto do LTV-03.
  - **Evidência do LTV-03 que ancora a escolha (NÃO reabrir):** renda SOZINHA colapsa ao controlar maturidade → o carregador é o COMPOSTO `score_priorizacao`, não renda pura. SEM eixo de churn-90d (é maturidade, −0.394, atributo de unidade). SEM penalidade de concorrência/densidade como driver principal (n_conc_1km +0.278 marginal e endógeno; residual/oferta NEGATIVOS −0.19/−0.22 → não entram como bônus).

### 1.2. Fórmula (régua 0–100, clip)
```
captacao_norm   = score_priorizacao                     # já 0–100 (LIDO do M1)
retencao_norm   = 100 * percentil_nacional(retencao_prevista_territorial)   # 0–100
score_m2        = clip( w_cap * captacao_norm + w_ret * retencao_norm , 0, 100 )
```
- **`retencao_prevista_territorial`** = predição do modelo do eixo retenção (§3), aplicada a TODOS os hexes com as features disponíveis (não só às 56 unidades — o score é territorial). A CALIBRAÇÃO do modelo usa as 56 unidades; a APLICAÇÃO é ao universo de hexes.

### 1.3. Pesos propostos (RECOMENDADA marcada)
| Variante | w_cap | w_ret | Justificativa |
|---|---:|---:|---|
| **A (RECOMENDADA)** | **0.50** | **0.50** | Equilíbrio captação↔retenção; o LTV-03 mostrou o território prevendo retenção mas sem magnitude para dominar o eixo executivo de demanda. 50/50 explicita "abrir onde há demanda E ela permanece" sem subverter o M1. |
| B | 0.60 | 0.40 | Preserva primazia do eixo executivo de captação (M1), retenção como refino. |
| C | 0.40 | 0.60 | Prioriza permanência; só se o eixo retenção passar folgadamente na validação (R²_oof do eixo retenção materialmente > 0 e > baseline). |

- **Critério objetivo de escolha entre A/B/C (mecânico, a decidir no gate):** default = **A (50/50)**. Migrar para **C** SÓ se, na validação (§3), o eixo retenção calibrado superar o `score_priorizacao` sozinho como preditor de `LTV_PROSPECTIVO_12M_MEDIANO` (R²_oof do modelo multivariado > R²_oof de `score_priorizacao` isolado, IC sem sobrepor). Migrar para **B** se o eixo retenção NÃO superar `score_priorizacao` sozinho mas ainda passar o NO-GO (§3.3). Se o eixo retenção falhar o NO-GO honesto (§3.3), o M2 NÃO se justifica e o bloco encerra sem score (desfecho legítimo — DEC-008).
- **Nota de produto:** os pesos finais são decisão do humano (Pergunta 1). O Planner recomenda **A**.

## 3. Método de validação honesto (DEC-008)

### 3.1. Alvo e universo
- **Alvo da validação:** o eixo retenção do M2 prediz `LTV_PROSPECTIVO_12M_MEDIANO` **agregado por unidade, FORA-DE-FOLD** (regra canônica do epic: LTV só no agregado por unidade).
- **Universo de calibração:** N=56 unidades com `hex_id` notna (eixo ranking do LTV-03). `USAR_RANKING`='Sim' é o filtro admissível; unidades sem prob. absoluta confiável entram só no ranking (não há uso de valor absoluto de LTV aqui — é ordenação/regressão de ranking). Haircut ~20% NÃO se aplica (não usamos volume absoluto de churn).

### 3.2. Protocolo (PROIBIDO R² in-sample e `fit(X,y)→predict(X)`)
- **k-fold repetido** (proposto: **5 folds × 5 repetições**, seed fixo `SEED=42` via `np.random.default_rng`) sobre as 56 unidades, com fallback a **LOO** (N pequeno). Toda métrica é **out-of-fold**.
- **Modelo simples primeiro (DEC-008):** regressão linear regularizada (Ridge) ou Spearman-ranking linear sobre as features territoriais padronizadas. Começar com 1 preditor (`score_priorizacao`) e só então o multivariado; nunca R² in-sample.
- **Métrica:** R²_oof (fora-de-fold) E Spearman rho_oof (predito × observado), ambos com **IC95 bootstrap** (≥1000 reamostras, seed fixo) — reusar o padrão `_bootstrap_spearman_ci` do LTV-03.
- **Baseline obrigatório:** média do alvo (predizer a média fora-de-fold). O modelo só "vale" se R²_oof > 0 e IC não cruza zero vs baseline.
- **Controle de maturidade como COVARIÁVEL (não feature por hex):** derivar `maturidade_meses` por unidade de `data/staging/growth_api_historico.parquet` (campo `inauguracao`, DD/MM/YYYY; dedup para 1 linha/unidade via `groupby('unidade').first()`; join por `normalizar_unidade`; snapshot 2026-04-17; **clip de outliers** — há valores negativos e >600 meses). Rodar a validação (a) sem controle e (b) com maturidade como covariável adicional no modelo de validação, reportando ambos. A maturidade NUNCA entra no `score_m2` por hex (é atributo de unidade — §Guardrails).

### 3.3. Critério mecânico de NO-GO honesto
O eixo retenção do M2 **só se justifica** se, no melhor modelo territorial out-of-fold:
- **R²_oof > 0 E IC95 não cruza zero** (supera o baseline da média); **E**
- rho_oof(predito × observado) **≥ 0.30** com IC não cruzando zero (relevância material, mesmo piso do LTV-03).

Se NÃO satisfeito → **NO-GO honesto**: o M2 territorial de retenção não bate o baseline; declarar no relatório e **não forçar**. Fallback aprovado no gate (Pergunta 4): (i) encerrar o bloco sem score; OU (ii) degradar o eixo retenção para o **próprio `score_priorizacao` como proxy de retenção** (w_ret carregado pelo composto, sem modelo novo) — o que reduz o M2 a uma reponderação de `score_priorizacao`, honesta mas de valor incremental baixo. Recomendação do Planner: **(i)** se o multivariado não superar `score_priorizacao` sozinho.

Adicionalmente, se o modelo multivariado **não** superar `score_priorizacao` **sozinho** (mesmo passando o NO-GO absoluto), o eixo retenção colapsa para `score_priorizacao` isolado → variante de peso **B** e nota explícita de que "retenção não agrega além do composto".

### 3.4. Flag de extrapolação
`flag_extrapolacao=True` para hexes cujas features caem fora do envelope (min–max ou quantis 5–95) das 56 unidades de calibração (o M2 nesses hexes é extrapolação — sinalizado, não ocultado).

## Riscos técnicos
- **N pequeno (56; 49 nas features de censo)** — variância alta; validação out-of-fold pode dar R² fraco/negativo (NO-GO honesto legítimo).
- **Colinearidade** captação↔retenção: ambos os eixos derivam de `score_priorizacao` → o M2 pode ser quase-monotônico em `score_priorizacao` (a reponderação agrega pouco). Mitigação: o critério de §1.3/§3.3 exige que o eixo retenção supere `score_priorizacao` sozinho, senão colapsa (honesto).

- **Seleção de sobreviventes + 32 sem hex_id (36%)** — universo N=56 pode não representar a rede; caveat declarado.
- **Outliers de maturidade** (negativos, >600 meses) — exige clip/winsorize antes de usar como covariável.
