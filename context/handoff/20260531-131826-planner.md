## Recomendação analítica revisada
**(a) NÃO recalibrar o M1 agora. Manter `renda=0.40` / `pop=0.60` e a fórmula atual do M1**,
agora corretamente enquadrada: o M1 é a camada EXECUTIVA (municípios/ranking de carteira), NÃO o
score operacional primário — esse papel é da camada censitária. **ACOPLADA** a uma recomendação
POSITIVA e acionável: **abrir um novo bloco read-only `BLK-SCORE-04`** de backtest MULTIVARIADO
das features mercado/censitárias reais (listadas acima) contra `alunos_recorrentes`, como base de
evidência ANTES de qualquer recalibração/enriquecimento de score. Isso responde DIRETAMENTE à
pergunta do usuário sobre "outras variáveis".

Justificativa honesta com os números (BLK-SCORE-02 + exploração desta revisão):

1. **Sinal do M1 é nulo, não "errado".** `score_priorizacao` (AGG, N=353) tem Spearman
   rho = **-0.004** (p=0.948), IC95% bootstrap **[-0.104, +0.094]** — o IC atravessa zero por
   larga margem. Não há direção a corrigir, logo não há pesos a recalibrar.

2. **A diferença pop>renda está dentro do ruído.** Decomposição (357/391 hexes casados; AGG
   N=346): `renda_pct_nacional` rho=**+0.067** (p=0.214, n.s.); `pop_pct_nacional` rho=**+0.095**
   (p=0.077, n.s.). Ambos fracos e não-significativos; diferença de 0.028 n.s. Mover peso
   renda→pop com base nisso seria **sobreajuste a ruído**. O peso atual JÁ favorece pop
   (0.60 vs 0.40), na mesma direção do achado fraco — não há inversão a fazer.

3. **NÃO há feature nova usável dentro do M1.** As únicas colunas reais do M1 são `renda` e `pop`;
   `n_domicilios`/`densidade_dom` estão 100% zeradas (placeholders). A exploração read-only
   confirma: rho indefinido para as zeradas; `renda_per_capita` +0.074 (n.s.) e `pop_total`
   +0.114 sobre a base estrutural — fracos. Não há matéria-prima para um M1 multivariado HOJE.

4. **Validade externa limitada para recalibrar o M1.** Desfecho `alunos_recorrentes` é de unidades
   JÁ existentes; o M1 mede atratividade estrutural para EXPANSÃO. Ausência de correlação pode
   refletir seleção/maturação (compressão de variância), não erro de peso. §5 do backtest reforça:
   maturação indisponível, heterogeneidade entre redes, N pequeno (EngCorpo N≈34), hex por
   centroide, rótulo EngCorpo estimado.

5. **O sinal positivo está nas camadas certas, e elas são as operacionais.**
   `score_setor_2022_calibrado` (censitário = primário operacional) é o único positivo
   significativo (rho=+0.148, IC [+0.052, +0.251]). É justamente nessas camadas (censitária +
   mercado) que vivem as features ainda não-validadas com potencial de sinal — alvo do BLK-SCORE-04.
   Usar a performance do censitário para mexer no M1 seria erro de escopo.

**Por que esta recomendação é melhor que "só manter":** o handoff anterior parava em "não
recalibrar". Esta revisão mantém isso (correto) E aponta o caminho de VALOR real para a pergunta
do usuário: as variáveis adicionais existem, mas FORA do M1 — então o próximo passo certo é
medi-las read-only (BLK-SCORE-04), não recalibrar o M1 às cegas nem inventar features zeradas.

**Trade-off declarado:** manter 0.40/0.60 preserva estabilidade, reprodutibilidade e o guardrail
M1, ao custo de não "agir" sobre um backtest fraco — custo correto, pois o M1 nem é o score
operacional primário. O valor incremental vem do BLK-SCORE-04, não de mexer no M1.
