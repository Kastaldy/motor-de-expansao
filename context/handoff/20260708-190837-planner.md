def test_flag_dentro_envelope_nao_altera_dre() -> None:
    """m2 fora do envelope (3001) NÃO altera DRE vs m2 dentro (1500) com mesma premissa.

    Garante que flag_fora_envelope é apenas informativa — a margem_ebitda_pct

    r_dentro = analisar_viabilidade_ponto(
        -23.9, -46.3, 1500.0, 20000.0, 938.0,
        base_calibracao_df=None, setores_df=None,
    )
    r_fora = analisar_viabilidade_ponto(
        -23.9, -46.3, 3001.0, 20000.0, 938.0,
        base_calibracao_df=None, setores_df=None,
    )
    assert r_fora.flag_fora_envelope is True
    assert r_dentro.flag_fora_envelope is False
    # DRE difere porque m2 difere (custo/m2 muda) — o ponto do teste é que a FLAG
    # não causa alteração além do que a variação de m2 já causa normalmente.
    # Verificamos que os resultados existem e são finitos em ambos os casos.
    assert math.isfinite(r_dentro.viabilidade.margem_ebitda_pct)
    assert math.isfinite(r_fora.viabilidade.margem_ebitda_pct)
    # flag_fora_envelope é True no r_fora, mas o DRE ainda roda normalmente.
    assert r_fora.viabilidade.faturamento_mensal_steady >= 0

## Confirmações do Planner

### Posição do campo no dataclass
- Todos os campos **sem** default terminam em `grade_sensibilidade` (linha 93 do arquivo atual).
- Os campos **com** default já existentes são: `alunos_balcao_premissa=0.0`, `alunos_agregadores_premissa=0.0`, `alunos_para_margem_alvo=0.0`, `demanda_fonte=DEMANDA_FONTE_PREMISSA`.
- O novo `flag_fora_envelope: bool = False` vai **após** `demanda_fonte` — posição segura, sem `TypeError`.

### `__all__` atualizado
Adicionados `"ENVELOPE_MIN"` e `"ENVELOPE_MAX"` ao `__all__`, permitindo importação direta nos testes.

### Testes de regressão (BLK-VIAB-03/04) não serão afetados
- `test_batch_viabilidade.py` chama `analisar_viabilidade_ponto` com m2=1500 (dentro do envelope) → `flag_fora_envelope=False`; campo novo sem default não quebra chamadas existentes porque é keyword com default.
- `test_backtest_viabilidade.py` não chama `analisar_viabilidade_ponto` diretamente; não sofre impacto.
- Todos os testes existentes em `test_viabilidade_ponto.py` usam m2=1500 → `flag_fora_envelope=False`; nenhum assert existente verifica o campo novo, então nenhum teste existente quebra.

### Comportamento byte-idêntico
- Para qualquer `m2 ∈ [600, 3000]`: `flag_envelope=False`; o campo `flag_fora_envelope=False` é o default — o resultado é byte-idêntico ao atual (campo extra com valor padrão).
- Para `m2` fora do envelope: `flag_fora_envelope=True`; DRE/faixa/grade continuam calculados normalmente — **apenas** o campo informativo muda.
