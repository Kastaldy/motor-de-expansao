## O que foi feito
Implementado, conforme as 5 decisões fechadas do Planner, um módulo de validação read-only de schema no caminho de load do dashboard, integrado nos dois pontos exatos antes de `_prepare_dataframe`:

1. Criado `src/motor_expansao/dashboard/schemas.py` (NOVO):
   - `SchemaValidationError(ValueError)`.
   - `validate_dashboard_frame(df, *, source) -> None`, read-only (não muta nem reatribui colunas; `pd.to_numeric(errors="coerce")` vive só em variável local). No-op para `df is None` ou `df.empty`.
   - Ordem das checagens: (b) colunas obrigatórias via `REQUIRED_COLUMNS` importado de `constants.py`; (c) chaves `hex_id`/`uf` não-nulas; (d) `hex_id` H3 válido via `h3.is_valid_cell` sobre os ÚNICOS (`dropna().astype(str).unique()`), amostra ≤5 inválidos; (e) por coluna de score: coerção numérica local → dtype-check (não-numérico que coage para NaN onde havia valor → "nao e conversivel a numerico") + range `[0,100]` tolerando NaN (`mask=numeric.notna()`).
   - Constantes `_SCORE_RANGE_REQUIRED = ("score_priorizacao","hex_score_estrutural")` (⊂ REQUIRED_COLUMNS) e `_SCORE_RANGE_OPTIONAL` (4 scores, checados só se `col in df.columns`). Toda mensagem cita `source` + coluna + invariante.
2. Integrado em `streamlit_app.py::_read_m1_frame`: `validate_dashboard_frame(df, source=str(DATASET_PATH))` entre `_read_parquet_subset(...)` e `_prepare_dataframe(df)`; import `from motor_expansao.dashboard.schemas import validate_dashboard_frame` posicionado entre os imports de `...pages` e `...utils` (ordem alfabética para passar no ruff I001).
3. Integrado em `src/motor_expansao/dashboard/data.py::read_enriched_uf_partition`: `validate_dashboard_frame(frame, source=f"{base} (uf={uf})")` após `to_pandas()`/early-return-empty e ANTES de `_prepare_dataframe(frame)`; import adicionado após o bloco `constants`. Sem ciclo de import (schemas→constants apenas; data→schemas+constants).
4. Criado `tests/unit/test_schema_validation.py` (NOVO, 16 testes): caso feliz; não-mutação (`.copy()` + `assert_frame_equal`); NaN tolerado (obrigatório e opcional); coluna obrigatória faltante; dtype errado em score; score fora de `[0,100]` (superior e inferior, checando min/max na mensagem); chave nula (`uf` e `hex_id`); `hex_id` inválido; frame vazio e `None` (no-op); coerência `set(_SCORE_RANGE_REQUIRED) <= set(REQUIRED_COLUMNS)`; disjunção dos opcionais. hex_id reais via `h3.latlng_to_cell(...,7)`.

ACHADO/ajuste de fixtures de teste: a integração no caminho real fez 4 testes pré-existentes de `tests/integration/test_streamlit_app.py` falharem porque usavam `hex_id` sintéticos não-H3 (`"a"`, `"hSP1"`, `"hSP2"`, `"hRJ1"`) que fluíam pelos entry points agora validados (`load_data`/`_read_m1_frame`, `read_enriched_uf_partition`/`load_uf_slice`, `main`). A validação estava CORRETA ao rejeitá-los. Conforme guardrail (não relaxar o H3-check nem o escopo), corrigi os FIXTURES desses 4 testes para usar células H3 res-7 reais (`_HEX_SP1/_HEX_SP2/_HEX_RJ1` via `h3.latlng_to_cell`), sem tocar na lógica testada. Tests que usam hex fake mas chamam helpers diretos (ex.: `enrich_dashboard_data`, `apply_global_filters`) seguem passando — confirma que os pontos de integração são exatamente os dois pretendidos. NÃO foi tocada nenhuma base/artefato real; só fixtures in-memory de teste.
