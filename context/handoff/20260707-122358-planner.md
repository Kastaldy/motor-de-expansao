### 1. Estratégia de varredura e substituição (metodologia geral)
1.1. **Não fazer substituição global cega de palavras.** Trabalhar call site por call site, usando os
     seguintes grep-anchors para localizar strings de EXIBIÇÃO (rodar em `pages.py`, `components.py`,
     `streamlit_app.py`, `data.py`):
   - Chamadas diretas: `st\.(caption|markdown|info|warning|success|error|write|title|header|subheader)\(`,
     `st\.metric\(`, `st\.multiselect\(`, `st\.selectbox\(`, `st\.expander\(`, `st\.text_input\(`,
     `st\.button\(`, `st\.download_button\(`, `help=`, `placeholder=`, `label=`.
   - Dicts de rename para exibição: `\.rename\(columns=\{` — nesses dicts, a CHAVE (esquerda) é sempre o
     nome real da coluna do DataFrame (NUNCA tocar) e o VALOR (direita) é o cabeçalho exibido (acentuar).
     Exemplo confirmado: `components.py:2667,2675,2750,2755,2761,2892,2906` e `pages.py:1696,1739,2092,
     2123,2372,2725,2906` têm `"nome_municipio": "Municipio"` → o VALOR vira `"Município"`; a CHAVE
     `nome_municipio` fica intocada.
   - `column_config.*Column(...)` — o argumento `label=`/primeiro posicional de exibição é editável; o nome
     da coluna (chave do dict `column_config={...}`) NUNCA.
   - HTML dentro de `st.markdown(..., unsafe_allow_html=True)` — texto dentro de tags (`<h1>`, `<p>`,
     `<strong>`, `<span class="badge">`) é exibição; atributos (`class=`, `style=`, `data-testid=`) NUNCA.
1.2. **Critério prático de exclusão (NUNCA tocar mesmo que pareça "palavra sem acento"):**
   - Lado esquerdo de `.isin(...)`, `==`, dict de cores (`FAIXA_COLORS`, `COLOR_MODES`/`OVERLAYS` — as
     CHAVES `"m1"`,`"hibrido"`,`"censitario"`,`"residual"`,`"dominio"`,`"concorrentes"`,`"ultra"` etc. ficam
     intocadas; só o valor `"label"` dentro de cada dict é exibição, ver item 1.4).
   - `key=` de widgets e `st.session_state[...]` — ex.: `coord_search_input`, `dashboard_active_tab`,
     `relpon_lote_fila`, `btn_gerar_pdf_topo`, `multihex_cenario`, `dominio_mun` (`pages.py:1867`),
     `plano_mun` (`pages.py:2042`).
   - Seletores CSS `.st-key-*` dentro de `inject_styles` (`pages.py:154,358-448` e o CSS que referencia
     `.st-key-dashboard_active_tab`, `.st-key-nav_search_bar`, `.st-key-btn_gerar_pdf_topo` — linhas
     337-448 e os testes de CSS em `test_streamlit_app.py:4647,4650`).
   - Valores brutos de `FAIXA_ORDEM`, `HYBRID_ELIGIBILITY_ORDER` (ver item 2), nomes de coluna de DataFrame
     em qualquer lugar (`score_priorizacao`, `nome_municipio`, `cod_municipio`, `faixa_oportunidade`,
     `elegibilidade_hibrida`, `cobertura_censitaria_bucket`, `qualidade_camada`, etc.), slugs (`_slug()`,
     `_relmun_key_slug`).
   - Comentários de código (`#`, docstrings) — o escopo do bloco é "texto voltado ao usuário"; comentários
     não são user-facing. Pode acentuar por cortesia se for trivial, mas NÃO é obrigatório e não deve
     inflar o diff — priorizar só strings realmente renderizadas.
1.3. **Amostra de validação (usar ANTES e DEPOIS, critério de aceite do bloco):** grep case-sensitive por

     linhas com `#` no início e nomes de coluna conhecidos). Meta: ~0 fora de identificadores/comentários.
1.4. **Labels de dicts de configuração que são SEMPRE exibição (chave = identificador interno, valor =
     texto exibido) — podem ser acentuados diretamente, sem camada de label extra:**
   - `COLOR_MODES` (`dashboard/constants.py:360-391`): valores `"label"` — `"Hibrido"→"Híbrido"`,
