## Decisão-chave (flags `--input-type/--output-type` por modo, com `-i`)
Raciocínio: com `cp SRC DST && sops -e -i DST` o SOPS lê e grava o MESMO arquivo (DST), já em `secrets/` com sufixo que casa `path_regex`. A inferência de tipo passa a ser pela extensão do DST.
- **dotenv** (`env.enc.env` → termina em `.env`): SOPS infere dotenv pela extensão, MAS o conteúdo copiado é dotenv `KEY=VALUE` e a regra `.*\.enc\.env$` tem `encrypted_regex: '^.*$'` (encripta valor-a-valor). Para remover ambiguidade e espelhar o workaround do fechamento real de 2026-05-29, **MANTER `--input-type dotenv --output-type dotenv`**. É inócuo (input==output==DST já em dotenv) e explícito.
- **binary** (`Caddyfile.enc`, `authelia.db.sqlite3.enc` → terminam em `.enc`): a extensão `.enc` NÃO é reconhecida por SOPS; sem flag ele tentaria parsear como JSON/YAML e falharia/corromperia conteúdo (Caddyfile não é YAML; sqlite3 é binário). **OBRIGATÓRIO MANTER `--input-type binary --output-type binary`** — não é opcional.
- **yaml** (`*.enc.yaml` → termina em `.yaml`): SOPS infere YAML pela extensão. **SEM flags** (mantém o comportamento atual do modo `yaml`).

Conclusão para o Builder: dotenv mantém flags, binary mantém flags (obrigatório), yaml sem flags. Não inventar nada além disso.

   ```bash
   case "${mode}" in
     dotenv)
       cp "${src}" "${dst}"
       if ! sops --input-type dotenv --output-type dotenv -e -i "${dst}"; then

         echo "ERRO: falha ao encriptar ${dst} (dotenv); DST removido." >&2

       if ! sops --input-type binary --output-type binary -e -i "${dst}"; then

         echo "ERRO: falha ao encriptar ${dst} (binary); DST removido." >&2
         return 1

         return 1
       fi
       ;;
     *)
       echo "ERRO: modo desconhecido ${mode}." >&2
       exit 1
       ;;
   esac
   ```

## Riscos técnicos
- `set -euo pipefail` ativo: a guarda do `sops` PRECISA ser `if ! sops ...; then rm -f; return 1; fi`; um `sops ...` solto abortaria o script antes do `rm -f`, deixando plaintext (o DST recém-copiado) órfão em `secrets/`. Esse é o ponto crítico — Builder não pode usar `&&` nem chamada solta.
- Modo binary SEM `--input-type/--output-type binary` corromperia o conteúdo (extensão `.enc` não reconhecida). Flags são obrigatórias nesse modo.
- Idempotência: re-rodar faz `cp SRC DST` sobre um DST já encriptado, sobrescrevendo-o com o SRC em claro antes do `sops -e -i`. Isso re-encripta a partir do SRC original (comportamento esperado). Não há corrida em que o DST encriptado anterior seja lido como SRC — o SRC é sempre o arquivo de origem fora de `secrets/`.
- Divergência doc↔script se só um for corrigido: ambos têm de espelhar as mesmas flags por modo.
