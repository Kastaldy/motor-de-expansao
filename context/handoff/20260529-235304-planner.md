## Tratamento do sys.path.insert / ROOT=parents[N]
Profundidade ANTES: `jobs/pipelines/X.py` -> `parents[0]=pipelines`, `parents[1]=jobs`, `parents[2]=raiz_repo`.
Profundidade DEPOIS: `src/motor_expansao/pipelines/X.py` -> `parents[0]=pipelines`, `parents[1]=motor_expansao`,
`parents[2]=src`, `parents[3]=raiz_repo`.

**Regra mecânica única**: em TODO módulo movido que define `ROOT`/`BASE`/`BASE_DIR = Path(__file__).resolve().parents[2]`,
trocar `parents[2]` por `parents[3]`. Isto preserva `ROOT / "data" / ...` apontando para a raiz do repo. Esta é a ÚNICA
alteração de valor permitida (exceção mecânica controlada, registrada explicitamente).

**`sys.path.insert(0, str(ROOT))`**: nos 8 módulos que o têm, ele é VESTIGIAL para resolução de imports após a FATIA-1
(nenhum módulo importa bare-root; todos importam `motor_expansao.*` ou `jobs.pipelines.*->motor_expansao.pipelines.*`).
Decisão: **REMOVER as 2 linhas `import sys` + `sys.path.insert(0, str(ROOT))`** desses 8 módulos, mas **MANTER a linha
`ROOT = ...parents[3]`** (recalculada), porque ROOT segue necessário para caminhos de dados. Remover `sys.path.insert`
