### O que o teste verifica
`test_classico_template_recente_inalterado` (linha 450, `tests/unit/test_relatorio_pontual_censitario_export.py`):

**Hipótese alternativa (a ser investigada):**

### FASE B — CORRIGIR o isolamento (somente em `tests/`)

**Princípio:** a correção ataca a CAUSA (estado global não revertido entre testes), nunca o sintoma.

**B1 — Caminho preferido: criar `tests/conftest.py` com fixture autouse de escopo `function`**

O conftest raiz (`tests/conftest.py`) não existe. Criá-lo com uma fixture que reseta os caches de `competitors.py` após cada teste. Isso é cirúrgico porque só afeta testes que poluem o cache, e é transparente para testes que já fazem limpeza manual:

```python
# tests/conftest.py
from __future__ import annotations
import pytest

@pytest.fixture(autouse=True)
def _reset_competitors_cache():
    """Reseta estado global de competitors.py entre testes.

    _ICON_CACHE e _ATLAS_CACHE sao dicionarios de modulo que sobrevivem entre testes
    quando preload_logos() e chamado sem teardown correto. _competitor_icon_svg e
    _ultra_icon_svg sao @functools.cache (SVG puros, sem logo PNG) — serao limpas
    pelo cache_clear apenas se o Builder confirmar que tambem contribuem para o failure.
    """
    from motor_expansao.dashboard import competitors
    yield
    # Teardown: limpar estado APOS o teste
    competitors._ICON_CACHE.clear()
    competitors._ATLAS_CACHE.clear()
    competitors._competitor_icon_svg.cache_clear()
    competitors._ultra_icon_svg.cache_clear()
```

**B2 — Alternativa (se a causa raiz for outra):**
Se a bisseção revelar que o vetor é em `service.py` (`lru_cache` de `_carregar_malha`/`_carregar_pontos`) ou em `fpdf2` (`/CreationDate`), o Builder deve:

## Riscos técnicos

1. **Bisseção pode não convergir para `_ICON_CACHE`**: se o vetor for outro (ex.: `fpdf2` `/CreationDate` variável, `lru_cache` em `service.py`, ou estado de `pyproj`/`PIL`), o Builder deve seguir a evidência e resetar o estado real em `tests/conftest.py`.

2. **`/CreationDate` em fpdf2**: se `gerar_pdf_relatorio_pontual_censitario` embute timestamp variável no PDF (via `FPDF.output()` padrão), `antes != depois` sempre que os dois calls cruzarem um segundo de relógio — isso seria a causa raiz, não `_ICON_CACHE`. Nesse caso a solução é suprimir o campo via `conftest` (monkeypatch do `datetime.now` dentro do fpdf2) ou, se possível na versão instalada, chamar `pdf.set_creation_date(None)` — mas isso tocaria produção e requereria nova DEC.

3. **Fixture autouse global pode esconder bugs futuros**: usar `scope="function"` garante isolamento mas pode tornar mais custoso rodar a suíte completa se o reset chamar operações pesadas. `_ICON_CACHE.clear()` e `_ATLAS_CACHE.clear()` são O(n) simples; `cache_clear()` é O(1). Impacto esperado: < 1ms por teste.

4. **`test_api_analisar.py` scope=module**: o `client` é compartilhado entre todos os testes do módulo. Se algum override de `dependency_overrides` não for removido (ex.: `test_analisar_municipio_sem_base_404`), pode afetar testes subsequentes — mas esse risco é independente do BLK-FIX-14.

5. **Reprodutibilidade da ordem**: confirmar que `python -m pytest -q --cache-clear` sem `pytest-randomly` instalado reproduz o failure antes de iniciar a bisseção. Se `pytest-randomly` estiver instalado e ativo por default, usar `-p no:randomly` em todos os comandos de bisseção.
