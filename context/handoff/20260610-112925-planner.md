## Riscos técnicos
- **Contagem de camadas nos testes:** os testes de `hex_pesquisado` assumem exatamente 3 layers quando ligado (hex + search_pin + search_hex). Se o competitor ou ultra layer também estiverem presentes no `enabled_overlays` do teste, a contagem muda. Os testes devem usar `enabled_overlays` mínimo (só o overlay sendo testado) para controlar a contagem.
- **`deck.layers.append` mutabilidade:** pydeck permite `deck.layers.append` após construção; verificar que o deck não é congelado (em versões recentes do pydeck o atributo `layers` é uma lista mutável normal — comportamento observado em testes existentes de `build_analise_pontual_map`). Alternativa se append falhar: reconstruir o deck com `layers=[*deck.layers, ancora_layer]`.
- **Modo domínio e âncoras:** o path `if color_mode == "dominio": return build_dominio_map_figure(...)` faz `return` antes do bloco de pós-injeção do Passo 3.2. Para cobrir também o modo domínio (se Felipe desejar), capturar o retorno em variável local antes de retornar. Decisão: deixar como follow-up (fora do escopo mínimo), a menos que Felipe indique no gate.
- **Tooltip da âncora e `_shared_map_tooltip`:** o `ScatterplotLayer` usa `tooltip_title` como campo de texto no tooltip do deck. O tooltip html do deck (`_shared_map_tooltip`) usa `{tooltip_title}` e `{tooltip_line_*}`. O DataFrame da âncora deve incluir essas colunas (preencher com `""` as linhas não usadas).
- **`search_tooltip_source` nos builders:** os 3 builders também chamam `_apply_hex_tooltip_fields` para o caminho de `search_tooltip_source` (dentro do bloco `if search_hex_id is not None:`). Esses call-sites devem receber `show_discarded=show_discarded` para consistência do tooltip do hex pesquisado. Não é crítico (o hex pesquisado raramente tem `flag_pop_min_5k=False`), mas é correto fazê-lo.

### DV-2 — Tamanho/escala dos marcadores de âncora
**Proposta recomendada:** `radius_min_pixels=8`, `radius_max_pixels=20`, `get_radius=250` (metros).
**Justificativa:** raio de 250m mantém os marcadores visíveis a zoom nacional mas sem cobrir hexes inteiros a zoom local; bounds de 8-20px são os mesmos dos marcadores de cluster de concorrentes.

### DV-3 — Comportamento de `descartados_5k` DESMARCADO
**Proposta recomendada:** hexes <5k hab ficam visíveis com a cor do score normal (remoção apenas do cinza `_DISCARDED_FILL` e do label no tooltip). Não ficam transparentes/ocultos.
**Justificativa:** manter os hexes visíveis é mais informativo (o usuário vê onde existem hexes de baixa pop) e é o comportamento natural de "desligar o filtro visual de descartados".

### DV-4 — Legenda quando overlays estão desmarcados
**Proposta recomendada:** `render_pop_cut_legend()` some da legenda quando `"descartados_5k"` não está em `enabled_overlays`; `render_ancoras_dominio_legend()` aparece somente quando `"ancoras_dominio"` está em `enabled_overlays`. Nenhuma entrada de legenda para `hex_pesquisado` (o pin amarelo é autoexplicativo pela cor).
**Justificativa:** manter a legenda coerente com o estado visual atual do mapa; evitar entradas de legenda para camadas que não estão sendo exibidas.

### DV-5 — Estado default dos 3 overlays em produção
**Proposta recomendada:** manter os defaults já declarados em `OVERLAYS` de `constants.py` — `hex_pesquisado=True`, `descartados_5k=True`, `ancoras_dominio=False`. Nenhuma mudança em `constants.py`.
**Justificativa:** os defaults atuais são razoáveis: pesquisa e descartados ligados por padrão (comportamento original preservado), âncoras desligadas por padrão (feature nova, não deve mudar o visual padrão do mapa para todos).
