## Bloco executado
BLK-FIX-12 — Logos das concorrentes não aparecem no PDF do Relatório (API/bot)

## O que foi feito

Corrigidos os 3 pontos de falha que impediam os logos de concorrentes de aparecer no PDF gerado pela API/bot:

1. **`settings.py`**: `competitors_logos_dir` mudou de `Path = _DATA_DIR / "Logos"` para `Path | None = None`. O default era resolvido para `site-packages/data/Logos` (inexistente no container de produção); agora é o sentinel `None` (fallback explícito e seguro). Usa a forma moderna `Path | None` (o arquivo já tem `from __future__ import annotations`).

2. **`service.py`** (`gerar_pdf_ponto`): o guard de `logos_dir` passou de `Path(settings.competitors_logos_dir).is_dir()` (lançaria `TypeError` quando o campo é `None`) para `settings.competitors_logos_dir is not None and Path(settings.competitors_logos_dir).is_dir()`. Comportamento preservado quando o dir existe.

3. **`docker-compose.prod.yml`** (serviço `api`): adicionados a env `API_COMPETITORS_LOGOS_DIR: "/app/concorrentes"` e o volume `- /opt/motor-expansao/concorrentes:/app/concorrentes:ro`, espelhando o serviço `streamlit` (linha 41). O diretório já existe no host.

4. **`tests/unit/test_api_skeleton.py`**: 4 novos testes adicionados antes do bloco `settings: parsing de tokens/origins`. O 4º teste (tautologia fraca do Planner) foi substituído por um teste mais forte que replica o guard exato de `service.py` com `competitors_logos_dir=None` e verifica que o resultado é `None` sem exceção.

5. **`docs/api_geoespacial_deploy.md`**: atualizado o default de `API_COMPETITORS_LOGOS_DIR` de `data/Logos` para `None (não definido)` na tabela de envs (§4), e adicionada nova subseção "Volumes do serviço `api`" em §3 com a tabela completa dos 5 volumes.
