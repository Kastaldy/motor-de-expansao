### Decisão 1 — Formato de saída da API
- (a) JSON com KPIs do ponto (leve; o bot monta a mensagem).
- (b) PDF binário (7 páginas) inline.
- **(c) [REC] Ambos por negociação de conteúdo** — `POST /analisar` retorna JSON por padrão;
  `?formato=pdf` (ou `Accept: application/pdf`) devolve o PDF. Reaproveita
  `analisar_ponto_censitario_setores` (JSON) + `gerar_pdf_relatorio_pontual_censitario` (PDF).
- (d) JSON + link para PDF gerado sob demanda.
- **Razão da recomendação:** entrega o KPI leve para o bot E o relatório completo sem novo
  endpoint; ambos os geradores já existem e são puros/offline. (d) adiciona estado/armazenamento
  de arquivo sem necessidade no MVP.

### Decisão 2 — Autenticação
- (a) API key estática `X-API-Key` (mais simples).
- **(b) [REC] Token por consumidor/bot** — rastreia QUEM pediu o estudo; casa com BLK-EST-01
  (marca d'água + solicitante no PDF / logs LGPD).
- (c) Reuso do Authelia/JWT de produção.
- **Razão da recomendação:** rastreabilidade do solicitante é requisito a jusante (LGPD /
  marca d'água). Implementação no MVP pode ser uma tabela/lista estática de tokens→consumidor
  (sem IdP), evoluível para (c) depois.

### Decisão 3 — Superfície de endpoints do MVP (define a decomposição de G2+)
- **(a) [REC] Mínimo:** `GET /health` + `POST /analisar` (ponto censitário 1.5 km).
- (b) Acrescentar lookup de hex M1 / camada de mercado já no MVP.
- **Razão da recomendação:** entrega o caso de uso central (estudo por ponto para os bots) com
  superfície mínima e fronteira limpa; lookup M1/mercado vira bloco sucessor explícito
  (BLK-API-05) sem inflar G2. **Esta escolha parametriza a decomposição abaixo.**

### Decisão 4 — Entrada de coordenada
- (a) Apenas `{lat, lng}`.
- **(b) [REC] `{lat, lng}` E link do Google Maps** (parser extrai a coordenada).
- **Razão da recomendação:** os bots receberão links colados pelo usuário; o roadmap do PDF já
  prevê "parser de links Maps". O parser é utilitário puro de string→(lat,lng), sem tocar o motor.

### Decisão 5 — Raio de análise no MVP
- **(a) [REC] Fixo 1.5 km** (igual ao Relatório Pontual Censitário — `raio_km` default; método de
  interseção e `RAIO_CENSITARIO_DEFAULT_KM` INTOCADOS).
- (b) Parametrizável (exige revalidar limites e o método de interseção).
- **Razão da recomendação:** mantém o motor e o método de interseção intocados (guardrail de
  parâmetro canônico); parametrizar raio é evolução com validação dedicada (bloco futuro).

### Decisão 6 — Carimbo de versão/reprodutibilidade
- **[REC] Incluir** versão do contrato/score no JSON e no rodapé do PDF, para estudos antigos
  seguirem interpretáveis (item de reprodutibilidade do PDF estratégico).
- **Razão da recomendação:** custo marginal nulo, ganho de auditabilidade alto; alinhado ao
  carimbo de versão já praticado no projeto.
