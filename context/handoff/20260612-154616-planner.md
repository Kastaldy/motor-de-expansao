## Riscos técnicos
1. **Seletor `[data-baseweb="button-group"]` é mais amplo que o segmented_control**: pode afetar outros componentes baseweb que usem `button-group` no dashboard. Mitigação: o diagnóstico DOM confirmou que apenas o seletor de telas usa esse componente neste app; risco baixo. A verificação RENDER pós-Builder confirma visualmente.
2. **`gap: 8px` (sem eixo explícito) sobrescreve tanto row-gap quanto column-gap**: intencional — o Streamlit 1.58 injeta `gap: 4px 0px`; sobrescrever com `8px` uniformiza ambos. O seletor de telas é uma linha única, portanto row-gap é irrelevante na prática.
3. **Asserts novos vs baseline de 696/3-failed**: os 3 failed pré-existentes são alheios ao bloco CSS; os novos asserts verificam strings que serão inseridas pelas novas regras — zero risco de falha adicional.
4. **f-string dupla-chave**: o bloco CSS em `inject_styles()` usa f-string Python; chaves literais do CSS são escapadas como `{{}}`. O Builder DEVE usar `{{` e `}}` nas novas regras, não `{` e `}`. Risco real se o Builder esquecer.
