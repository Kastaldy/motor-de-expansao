### D2 — Conteúdo literal do `.mcp.json`
`command` = `${GRAPHIFY_PYTHON:-python}` (não `python` nu, não `python3`, não caminho absoluto):
- `.mcp.json` suporta `${VAR:-default}`; o default `python` funciona no Windows (única máquina ativa hoje);
- quem estiver em Linux/container define `GRAPHIFY_PYTHON=python3` **sem editar o arquivo versionado**;
- `GRAPHIFY_PYTHON` é exatamente o nome de variável que os próprios hooks do graphify usam — coerência;
- se um cliente não expandir a variável, o comando falha e o servidor é pulado: **mesmo modo de falha inerte** já aceito em D1.

`args` invoca o **módulo**, com o caminho do grafo **explícito** (o default é o mesmo, mas explícito é
testável e auto-documentado). Nome do servidor = `graphify` — **identificador ASCII, sem acento** (§2).

Deixar a aprovação manual reproduz exatamente o defeito que o bloco existe para corrigir ("depende de cada
pessoa decidir obedecer"). Uso `enabledMcpjsonServers: ["graphify"]` (estrito) e **não**
`enableAllProjectMcpServers` (abriria qualquer servidor futuro do arquivo). `.claude/` é GOVERNANÇA no
`loop_guard` → **não escala para Crítica**. A limitação continua documentada: pré-aprovação vale para quem
confia na pasta; quem não tiver a chave aprova por `/mcp`.

**Bônus decidido junto:** liberar no `permissions.allow` **só os verbos read-only** do graphify
(`query`, `path`, `explain`, `god-nodes`, `affected`). **NÃO** usar o glob `Bash(python -m graphify*)`: ele

`merge=graphify` ao `.gitattributes`**, path CRÍTICO (R2). O glob amplo seria uma escada para o guard.

### D4 — R10 / o hook divergente: versionar **só o `post-commit`**; `post-checkout` fica FORA
Decisão baseada na leitura dos dois arquivos, não em suposição:

| | `.git/hooks/post-commit` | `.git/hooks/post-checkout` |
|---|---|---|
| chamada real | `_rebuild_code(_root, changed_paths=changed, force=_force)` (linha 165) | `_rebuild_code(_root, force=_force)` — **sem `changed_paths`** (linha 157) |
| efeito | rebuild **incremental**, só os arquivos do commit | rebuild **de corpus INTEIRO** — o próprio comentário do hook assume: *"branch switch can touch arbitrary files; full rebuild path (no changed_paths) is correct here"* (linhas 147–149) |
| anti-loop | **sim** — sai cedo se só `graphify-out/` mudou (linhas 40–44) | não |

O caminho de corpus inteiro é o que produziu a divergência medida pelo BO (13.599 nós vs 7.560 versionados,
`graph.json` 10 MB → 15 MB, `.graphify_labels.json` curado sobrescrito, `context/handoff/` puxado para dentro
do corpus contra o recorte da §7). O log confirma o mecanismo:
`AST extraction: 575/575 uncached files` + 566 linhas `worker failed for ...\context\handoff\*.md` +
`backed up curated graph (5 files) -> 2026-07-28/` + `Rebuilt: 13599 nodes, 21063 edges`.

**Não dá para "ajustar o hook" para respeitar o recorte:** a assinatura de `_rebuild_code`
(`watch_path, changed_paths, follow_symlinks, force, no_cluster, acquire_lock, block_on_lock`) **não tem
parâmetro de exclusão**. Filtrar exigiria bifurcar lógica upstream dentro de um hook de 200 linhas que não é
nosso — dívida permanente. Opção descartada com evidência.

Portanto:
- **`.githooks/post-commit`** — versionado, **byte-idêntico** ao instalado (comentário do projeto vai no
  runbook, não dentro do arquivo vendorizado: arquivo upstream que a gente edita é arquivo que a gente
  mantém para sempre).
- **`.githooks/post-checkout`** — **NÃO versionado**, com o motivo escrito no runbook, na §7 e no teste.
- **Efeito colateral desejável:** quando alguém rodar `git config core.hooksPath .githooks`, o git deixa de
  ler `.git/hooks/` por completo → o `post-checkout` divergente **para de disparar** nesta máquina. O passo do
  runbook vira conserto, não enfeite.
- **O que NÃO muda:** o `post-commit` também escreve em `graphify-out/` a cada commit. `git checkout --
  graphify-out/` antes de commitar e **commit por path** continuam obrigatórios.
- **Registrado como follow-up (não é deste bloco):** decidir se `graphify-out/graph.json` continua versionado
  ou vira artefato de CI. Ter artefato gerado + versionado + reescrito por hook é a raiz do incômodo.
