1. **Criar `src/motor_expansao/dashboard/relatorio_municipal.py`** (módulo NOVO, disjunto).

   Recomendação: **reimplementar os helpers de layout no módulo novo** (isolamento total: alterar
   o municipal nunca pode arriscar o pontual). As constantes de cor podem ser importadas.

2. **Definir a função pública de agregação** `agregar_municipio(df, *, nome_municipio, dominio_df=None) -> dict`
   no módulo novo. READ-ONLY (só lê colunas; nunca recalcula score). Filtra `df` por
   `df["nome_municipio"] == nome_municipio` (fallback `cidade`) e computa o dicionário canônico
   de métricas (abaixo). Esta função é o ÚNICO ponto que toca dados — fácil de testar isolado.

   **Dicionário canônico `municipio_result` (proposto):**
   - `nome_municipio`, `uf` (de `df["uf"]` do slice ou `selected_uf`).
   - `n_hex_total` = nº de hexes do município no `df`.
   - `espaco_para_academias` (Página 2/8) — **fórmula recomendada (D1):**
     `round( Σ oferta_efetiva_disponivel[hexes amarelos] / 2500 )`, onde "hexes amarelos" =
     `faixa_oportunidade ∈ {prioridade_maxima, alta}` **AND** `flag_pop_min_5k == True`
     **AND** `oferta_efetiva_disponivel > 0`. Guardar também os parcelados por hex para a caixa
     "Como calculamos" (até 5 maiores + "…").
   - `soma_oferta_amarelos` (numerador antes do ÷2500), `n_hex_amarelos`.
   - `score_censo_medio`, `score_censo_max` = média/máx de `score_setor_2022_calibrado` (NaN-safe).
   - `mercado_disponivel_pessoas` (Página 4) — **D4 recomendado:** `Σ oferta_efetiva_disponivel`
     (em alunos = "pessoas elegíveis sem academia") sobre o município. (NÃO recalcula; só soma a
     coluna oficial da camada de mercado.)
   - `pop_total_municipio` = `Σ pop_total_setor_2022` (fallback `Σ pop_total`), exibido como
     "Hab. totais".
   - `renda_per_capita_media` = média ponderada por `pop_total_setor_2022` de `renda_per_capita`
     (fallback média simples).
   - `penetracao_fitness_media` = média de `penetracao_fitness_mercado_estimada`.
   - `residual_total_alunos` = `Σ oferta_efetiva_disponivel` (mesmo de mercado_disponivel; Página 7).
   - `n_zonas` (Página 5/7), `zonas` = lista derivada de `dominio_df` (ver passo 3).
   - `n_ultra`, `n_concorrentes`, `concorrentes_por_rede` (dict rede→contagem) — preenchidos no
     passo 4 (geográfico).
   - `versao_contrato` = string de carimbo (ver D8), `metodo` = `"agregacao_municipal_h3_res7"`.

3. **Derivar as "zonas" (Página 5/6)** — `_zonas_do_municipio(dominio_df, nome_municipio) -> list[dict]`.
   **D2 recomendado:** usar `dominio_df` já em escopo (NÃO derivar clusters on-demand — o `df` não
   tem `cluster_id`). Agrupar `dominio_df[dominio_df["nome_municipio"]==nome]` por `cluster_id`,
   ordenar por `residual_incremental_capturado` desc, numerar Zona 1..N (cap em 3–4 como o
   template), e por zona expor: `zona_n`, `n_hex`, `tese_dominio` (moda), `residual_cluster`,
   `hex_ids`. **Fallback gracioso:** `dominio_df is None`/vazio/sem o município → `zonas=[]` e as
   Páginas 5–6 entram em modo simplificado (texto "Zonas de domínio não disponíveis para este
   município; rode `gerar_plano_expansao_dominio.py`."), sem exceção.

4. **Contagem geográfica de pins** — `_pins_no_municipio(df_muni, competitors_df, ultra_df) -> tuple`.
   **D6 recomendado:** como `competitors_df`/`ultra_df` não têm município, derivar `hex_id_res7`
   de cada pin (`h3.latlng_to_cell(lat,lng,7)`) e contar os que caem nos `hex_id` do `df_muni`.
   Reusar a coluna `hex_id_res7` já presente no parquet de concorrentes quando existir; para
   Ultra, computar via `h3` (helper local). Devolve `(n_ultra, n_concorrentes, dict_por_rede)`.
   Anti-PII: usar só `rede`/contagem, nunca nome/PII. (Alternativa mais simples se D6=(b):
   bbox do município — menos precisa nas bordas; Planner recomenda H3.)

### Fase 1 — mapas estáticos do município (imagens offline)

5. **`_render_mapa_municipio(...)` — imagem PNG offline via Pillow** (mesma stack do
   `censo_map.py`, mas SEM reusar `render_mapas_censitarios_combinados`, que é por-raio).

     (4 faixas do template mapeadas sobre as 10 bandas: Alto≥70 / Médio-alto 50–70 / Médio 30–50 /
     Baixo <30 — confirmar no gate, D5).

   - Página 5 (Domínio): hexes coloridos por `zona_n` (das zonas do passo 3) + pins.
