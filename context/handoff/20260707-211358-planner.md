### PASSO 1 — `carregar_base_calibracao`

```python
def carregar_base_calibracao(ultra_parquet_path: Path | str) -> pd.DataFrame:
    """Deriva a base de comparaveis (curva tamanho->densidade) do parquet Ultra.

    Retorna DataFrame com colunas ['metragem', 'alunos_por_m2'] (float),
    limpo: sem NaN, metragem>0 e alunos_por_m2>0. Nenhuma PII/geo propagada.
    """
```
Regras:
- Ler o parquet. Se `alunos_por_m2` **não** existir mas existirem `metragem` e
  `alunos_total`, derivar `alunos_por_m2 = alunos_total / metragem`. (Guard
  defensivo — na base real a coluna já existe; a diferença é 0.0.)
- Coercer `metragem` e `alunos_por_m2` via `pd.to_numeric(errors="coerce")`,
  `astype(float)`.
- Filtrar `np.isfinite` e `> 0` em ambas; `dropna`.
- Retornar **só** `["metragem", "alunos_por_m2"]`, `reset_index(drop=True)`.
- Se a base ficar vazia após limpeza → `raise ValueError("base de calibracao vazia após limpeza")`.

### PASSO 2 — `assign_tier_e_faixa`

```python
def assign_tier_e_faixa(
    m2: float, df_tiers: pd.DataFrame
) -> tuple[str, float, float, float, bool]:
    """Mapeia m2 -> (tier_label, p10, p50, p90, flag_extrapolacao).

    Usa _assign_tier(m2) para o rotulo e faz lookup da linha correspondente em
    df_tiers. Levanta ValueError se o tier nao existir em df_tiers.
    """
```
Regras:
- `label = _assign_tier(float(m2))`.
- `row = df_tiers[df_tiers["tier_label"] == label]`; se vazio → `ValueError`.
- Extrair `p10/p50/p90` como `float(row.iloc[0]["p10"])` etc. e
  `flag_extrapolacao = bool(row.iloc[0]["flag_extrapolacao"])`.
- Retornar `(label, p10, p50, p90, flag_extrap)`.

### PASSO 3 — `rodar_candidato`

```python
def rodar_candidato(
    row: pd.Series,
    base_calib_df: pd.DataFrame,
    df_tiers: pd.DataFrame,
) -> dict:
    """Roda o motor de viabilidade (coordless) para 1 candidato e monta o dict de saida."""
```
Lógica (ordem exata):
1. `m2 = float(row["ÁREA"])`, `aluguel = float(row["ALUGUEL"])`.
2. `tier_label, p10, p50, p90, flag_extrap = assign_tier_e_faixa(m2, df_tiers)`.
3. Chamar o motor **1 vez** com `demanda_premissa=p50` (cenário central), coordless:
   ```python
   res = analisar_viabilidade_ponto(
       lat=LAT_COORDLESS, lng=LNG_COORDLESS,
       m2=m2, aluguel_pedido=aluguel, demanda_premissa=p50,
       base_calibracao_df=base_calib_df,
       setores_df=None,   # COORDLESS explícito
   )
   ```
   (ticket_medio/margem_alvo/share_balcao ficam nos defaults do motor — 137 / 0.10 / 0.69.)
4. Calcular os 3 tetos via `aluguel_teto` diretamente, um por valor de demanda,
   aplicando o **mesmo split balcão/agregadores** que o motor usa internamente
   (`share_balcao=SHARE_BALCAO_DEFAULT=0.69`). Para não reimplementar o split,
   **reusar `res.aluguel_teto_calculado` para o teto p50** (já vem do motor com
   demanda=p50) e calcular p10/p90 chamando o motor 2× mais:
   - Opção escolhida (mais simples e à prova de divergência): chamar
     `analisar_viabilidade_ponto` **3 vezes** (p10, p50, p90), lendo
     `aluguel_teto_calculado` de cada resultado. O motor é puro e barato (23×3 ≈ 69 chamadas).
     - `teto_p10 = analisar_viabilidade_ponto(..., demanda_premissa=p10, setores_df=None).aluguel_teto_calculado`
     - `teto_p50 = res.aluguel_teto_calculado` (reusa a chamada do passo 3)
     - `teto_p90 = analisar_viabilidade_ponto(..., demanda_premissa=p90, setores_df=None).aluguel_teto_calculado`
   - **NÃO** importar/chamar `aluguel_teto` do simulador diretamente para evitar
     recriar o split de agregadores/personal; o import de `aluguel_teto` acima é
     opcional e pode ser removido se não usado. **Decisão: usar as 3 chamadas ao
     orquestrador** (fonte única de verdade do split). Remover o import de
     `aluguel_teto` do PASSO 0 se não for usado, para não deixar import morto (ruff F401).
5. Ranking e flags (decisões pré-fixadas):
   ```python
   margem_seguranca = teto_p50 - aluguel
   flag_robusto     = bool(aluguel < teto_p10)   # passa até no pior cenário (p10)
   flag_no_go       = bool(aluguel > teto_p50)   # inviável no cenário central
   ```
6. Serializar a grade de sensibilidade do cenário p50 (`res.grade_sensibilidade`,
   DataFrame 30×6) como **JSON string** via `res.grade_sensibilidade.to_json(orient="records")`
   → coluna `grade_sensibilidade_json`.
7. Montar e retornar o dict (colunas exatas no PASSO 5).

### PASSO 6 — Estrutura do relatório `.md`

Conteúdo (acentuação correta — regra permanente do CLAUDE.md §2):

- `Data de geração: {datetime.now():%Y-%m-%d %H:%M:%S}`

- **Tabela ranqueada por `margem_seguranca` DESC** com colunas:
  `| Rank | ID | NOME | ÁREA (m²) | ALUGUEL (R$) | Tier | Teto p50 (R$) | Margem seg. (R$) | Break-even (alunos) | Robusto | NO-GO | Extrap |`
  - `Robusto` = "SIM"/"-"; `NO-GO` = "NO-GO"/"-"; `Extrap` = "ATENÇÃO"/"-".
  - Valores monetários formatados sem casas decimais (`f"{v:,.0f}"`), demanda/alunos `f"{v:.0f}"`.
- Seção **Caveats**:
  - Aviso de extrapolação: listar os candidatos com `flag_extrapolacao=True` (esperado:
    `FORTALEZA_JARDIM_DAS_OLIVEIRAS`, 4.000 m², tier `>=3000` N=2) e alertar que o
    p50 do tier é instável.
  - Nota metodológica: ranking = `aluguel_teto(demanda=p50) − aluguel_pedido`;
    `flag_robusto` = aluguel < teto(p10); `flag_no_go` = aluguel > teto(p50).
    Defaults do motor: ticket R$137, margem-alvo 10%, share balcão 69%.
  - Nota DEC-009: demanda NUNCA prevista por lat/lng; coordless puro.
- **Somente ASCII em pontuação** para tokens que não são acento português: usar
  `-` (não `—`), `...`, `(c)` — mas o `.md` não passa por fpdf2, então acentos
  portugueses são livres; evitar apenas travessão/bullet unicode por consistência.
