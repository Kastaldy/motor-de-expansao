## Entendimento da tarefa
Estender os DOIS pontos de geração do Relatório Municipal em `pages.py`
(`render_relatorio_municipal_download_topo` e `render_relatorio_municipal_expander`) para,
quando `len(selected_cities) > 1`, gerar sob demanda (botão único "Gerar Relatorios (N)", com
progresso) um PDF por município e oferecer um `st.download_button` por município rotulado com o
nome — preservando o caso de 1 município byte-a-byte. READ-ONLY sobre o M1.

## Decisões técnicas resolvidas (criticidade Média — decididas aqui)

### D1 — Assimetria do expander (auto-gen vs botão)
MANTER a assimetria: no ramo `== 1` cada ponto conserva o comportamento ATUAL literal
(topo = botão-triggered; expander = AUTO-GERA sem botão). Só o ramo `> 1` é botão-triggered nos
dois pontos. Justificativa: "preservar o fluxo de 1 município byte-a-byte" é critério de aceite;
converter o expander de 1 município para botão seria regressão de UX em produção. Estrutura de
controle exata em cada função:
- `len(selected_cities) == 0`: comportamento atual de cada ponto (topo: `return` silencioso;
  expander: `st.info(...)`). Único ajuste de texto permitido (não afeta 1 município): trocar o
  texto do `st.info` do expander de "Selecione exatamente um municipio..." para
  "Selecione um ou mais municipios no filtro lateral para gerar o(s) Relatorio(s) Municipal(is)."
- `len(selected_cities) == 1`: bloco ATUAL literal, INTOCADO (mesmos `key`s de widget, mesma
  cache key `relmun_topo_payload::<nome>` no topo, mesmos textos de botão/spinner/warning, mesmo
  `render_download_relatorio_municipal(...)` no expander). NÃO refatorar este ramo.
- `len(selected_cities) > 1`: novo ramo de lote (D2–D4).

### D2 — Helper interno compartilhado (evita duplicar o loop)
Extrair UM helper privado de GERAÇÃO por município em `pages.py`, consumido SÓ pelo ramo de lote
dos dois pontos (o ramo `== 1` permanece inline e intocado, para garantia byte-a-byte). O ramo de
lote nos dois pontos difere só em `key`s de widget e chave de `session_state` — o miolo de geração
é idêntico e vive no helper. Assinatura recomendada (posicional `df`, resto keyword-only):

```python
def _gerar_payload_relatorio_municipal(
    df: pd.DataFrame,
    nome_municipio: str,
    uf: str | None,
    *,
    competitors_df: pd.DataFrame | None = None,
    ultra_df: pd.DataFrame | None = None,
    dominio_df: pd.DataFrame | None = None,
    censo_geo_dir: Path | None = None,
) -> dict[str, Any] | None:
    """Gera o payload (pdf_bytes/pdf_filename) de UM municipio reusando exatamente as MESMAS
    chamadas do fluxo de 1 municipio. Retorna None quando o municipio nao tem hexagonos
    (n_hex_total == 0) — o chamador emite o aviso individual. READ-ONLY M1."""
```

Corpo do helper = reproduzir, na MESMA ordem e com os MESMOS kwargs do ramo `== 1` atual
(pages.py ~3074–3113): `_resolve_bairros_por_hex_municipio(df, nome_municipio, uf, censo_geo_dir)`
→ `agregar_municipio(df, nome_municipio=..., uf=..., dominio_df=..., competitors_df=..., ultra_df=..., bairros_por_hex=...)`
→ se `municipio_result["n_hex_total"] == 0`: `return None` → filtro `df_muni`
(mesmo bloco `nome_municipio`/fallback `cidade`) → `render_mapas_municipio(df_muni, municipio_result, competitors_df=..., ultra_df=..., basemap=True)`
→ `gerar_payloads_download_relatorio_municipal(municipio_result, mapas)`
→ `return {"pdf_bytes": payloads.pdf_bytes, "pdf_filename": payloads.pdf_filename}`.
O helper NÃO chama `st.*` (nem warning nem spinner) — é a unidade TESTÁVEL sem mockar Streamlit;
progresso/warning/session ficam no chamador.

### D3 — Chaves de `session_state` e de widget (unicidade, sem colisão)
- Cache de lote em `session_state` = UM dict por ponto, com prefixo distinto do modo 1-município
  (`relmun_topo_payload::`) e distinto entre os dois pontos:
  - topo: `st.session_state["relmun_lote_topo_payloads"]`
  - expander: `st.session_state["relmun_lote_expander_payloads"]`
  Valor = `dict[str, dict]` mapeando `f"{uf or ''}::{nome_municipio}"` → `{"pdf_bytes","pdf_filename"}`.
  Reconstruído inteiro a cada clique em "Gerar Relatorios (N)"; sobrevive ao rerun do clique em
  qualquer `download_button` (não regera).
- Slug para `key` de widget: adicionar helper local minimalista (sem novo import — `re` NÃO está
  importado em pages.py): `def _relmun_key_slug(text: str) -> str: return "".join(c if c.isalnum() else "-" for c in str(text).casefold())`.
- `key` do botão de geração: `key="btn_gerar_relmun_lote_topo"` / `key="btn_gerar_relmun_lote_expander"`.
- `key` de cada download (inclui índice + UF + slug do nome → único mesmo com homônimos entre UFs):
  `key=f"dl_relmun_lote_topo_{i}_{_relmun_key_slug(uf or '')}_{_relmun_key_slug(nome)}"` e a versão
  `_expander_`. (Na prática `selected_ufs` traz 1 UF só — `uf` é o mesmo para todos —, mas incluir
  UF+índice blinda contra colisão.)
- Render dos downloads: iterar `selected_cities` na ordem de seleção e renderizar SÓ os municípios
  cujo payload existe no dict de lote (intersecção seleção-atual × cache) — isso oculta downloads
  de seleções antigas sem trabalho extra.

### D4 — Progresso do lote
Antes do loop: `prog = st.progress(0.0, text=f"Gerando 0/{n}...")` (n = `len(selected_cities)`).
No loop (i de 1..n): `prog.progress((i - 1) / n, text=f"Gerando {i}/{n}: {nome}...")` antes de
chamar o helper. Ao final: `prog.progress(1.0, text=f"{n}/{n} concluido")` e `prog.empty()`.
Município sem hexágonos (helper → `None`): `st.warning(f"Nenhum hexagono encontrado para '{nome}' no recorte carregado.")` e `continue` (NÃO aborta o lote). Fallback offline de tiles (DEC-011)
já é interno a `render_mapas_municipio(basemap=True)` — não replicar aqui.

  (DEC-011) já internos a `render_mapas_municipio(basemap=True)` — não paralelizar rede.
