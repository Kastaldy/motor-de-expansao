### Passo 2 — Seção: Autenticação (fonte: `auth.py`, `settings.py`)

Conteúdo a extrair:
- Header obrigatório: `Authorization: Bearer <token>` em **todas** as rotas exceto `GET /health`.

### Passo 3 — Seção: Endpoints (fonte: `main.py`, `routes/analisar.py`, `schemas/__init__.py`)

#### 3a. `GET /health`

- Sem autenticação.
- Resposta: `{"status": "ok", "environment": "<env>"}`.
- Disponível também em `GET /api/v1/health` (alias sem autenticação).
- Uso: liveness check do load balancer/compose.

#### 3b. `POST /api/v1/analisar`

**Request body** (`AnalisarRequest`):

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `lat` | float | Sim (se sem `maps_url`) | Latitude decimal |
| `lng` | float | Sim (se sem `maps_url`) | Longitude decimal |
| `maps_url` | string | Alternativa a lat/lng | Link do Google Maps (parser puro, sem rede) |
| `formato` | `"json"` / `"pdf"` | Não (default `"json"`) | Atalho de negociação no body |
| `rotulo` | string / null | Não | Nome do endereço/estabelecimento na capa do PDF |

Regra: fornecer `{lat, lng}` **OU** `maps_url` — ambos ausentes → 400.

**Negociação de conteúdo** (implementada em `routes/analisar.py`):
- JSON é o default.
- PDF é ativado por qualquer uma das 3 formas (em precedência):
  1. `Accept: application/pdf` no header da request
  2. `?formato=pdf` como query param
  3. `"formato": "pdf"` no body JSON

**Response JSON** (`AnalisarResponseJSON`) — campos exatos:
`lat`, `lng`, `raio_km`, `area_km2`, `metodo`, `n_setores`, `pop_total_raio`, `renda_per_capita_media_raio`, `densidade_pop_raio_hab_km2`, `score_setor_medio`, `score_setor_max`, `n_concorrentes`, `n_ultra`, `versao_contrato`, `versao_score`, `gerado_em`, `consumidor`.

**Response PDF**: `Content-Type: application/pdf`, `Content-Disposition: inline; filename="relatorio_pontual_censitario.pdf"`.

### Passo 5 — Seção: Formatos de localização aceitos (fonte: `coord.py`, `maps_geocoder.py`, `geo.py`)

Documentar **4 formatos de `maps_url`** (em ordem de prioridade no parser `coord.py`):

1. `!3d<lat>!4d<lng>` — pino exato do place (mais preciso).
2. `@<lat>,<lng>` — centro do viewport da câmera.
3. Query params: `?q=`, `?query=`, `?ll=`, `?sll=`, `?center=`, `?destination=`.
4. `"lat,lng"` cru — string simples separada por vírgula.

**Links compactados** (ex.: `maps.app.goo.gl/...`, `goo.gl/maps/...`): expandidos via `expandir_link_curto` (segue redirect HTTP) antes do parse — bot usa essa cadeia automaticamente.

**Bounding box de validação**: lat ∈ [-34.0, 5.5], lng ∈ [-74.0, -28.0] (inclui ilhas oceânicas).

### Passo 6 — Seção: Bot Telegram — Paulo (fonte: `telegram_bot.py`, `settings.py`)

Documentar o fluxo completo da máquina de estados:

**Diagrama de fluxo** (5 passos sequenciais):
```
1. Saudação  →  "Envie a senha de acesso"
2. Senha     →  correta → "Como posso te chamar?" | errada → repete pedido de senha
3. Nome      →  "Prazer, <nome>!" + menu [Relatorio | Ajuda] + "Me envie a localização"
4. Menu ativo:
   - "Relatorio" / /relatorio → pedido de localização
   - "Ajuda" / /ajuda        → mensagem de ajuda
   - /start                  → pedido de localização
5. Localização (qualquer mensagem não-comando):
   → ⏳ aviso imediato ("Estou gerando o PDF...")
   → resolve coordenada (Maps link / lat,lng / endereço+CEP)
   → se falhar: ❌ instrução de formatos aceitos
   → se OK: PDF + mensagem "Pronto!"
```

**3 formas de localização suportadas pelo bot**:
1. Link do Google Maps (completo ou compactado — expandido automaticamente).
2. `lat,lng` — ex.: `-21.9180,-46.6855`.
3. Endereço + CEP (geocoding: Selenium/Chrome primário → Google Geocoding API → Nominatim).

**Nome do bot**: "Paulo".

**Persistência de sessões**: `API_BOT_SESSOES_PATH` (default: `bot_sessoes.json` na raiz do repo). Permite reiniciar o bot sem deslogar usuários.

**Como rodar o bot** (com a API já no ar):
```bash
API_TELEGRAM_TOKEN=<token-do-botfather> python -m motor_expansao.api.telegram_bot
```

Tabela completa de erros da API — CONFIRMAR slugs exatos:

| HTTP | `codigo` | `detail` (exemplo) | Quando ocorre |
|---|---|---|---|
| 400 | `coordenada_invalida` | "Coordenada fora do Brasil" | lat/lng fora do bounding box; `maps_url` não parseável; ponto sem município na malha |
| 401 | `nao_autenticado` | "Token invalido" | Header `Authorization` ausente ou token inválido |

**Nota sobre 422**: FastAPI devolve 422 (sem `codigo`) para erros de validação do body Pydantic (ex.: body malformado). Não faz parte do contrato `{detail, codigo}` mas pode ocorrer.

## Riscos técnicos

### Resolvidos pelo Planner (leitura dos fontes confirmada):

- **`_VERSAO_SCORE`**: CONFIRMADO como `"score_setor_2022_calibrado"` em `service.py`.

- **Estados do bot**: o bot não tem estado `aguardando_local` como variável explícita — usa `etapa="login"` para o passo de nome; após isso qualquer mensagem não-comando é tratada como localização. O estado `autorizado` vive no dict `_sessoes[chat_id]`. Fluxo real: `saudou` (flag) → `autorizado` (bool) → `etapa="login"` (passo de nome) → menu livre.

### Riscos residuais para o Builder:
- **Gotcha de `API_CORS_ORIGINS`**: valor `["*"]` (lista) deve ser serializado como JSON string no env; string simples `*` é aceita pelo parser mas pode se comportar diferente. Mencionar claramente no doc.
- **Timeout do PDF no bot**: primeira chamada pode levar até 4 minutos (cold load dos parquets); bot usa `timeout=240`. Mencionar como expectativa normal de UX.
- **Chrome/Selenium no host local**: extra `[geocoder]` requer Google Chrome instalado no host além de `selenium`/`webdriver-manager`. Sem Chrome, geocoding de endereço+CEP cai em Nominatim silenciosamente.
