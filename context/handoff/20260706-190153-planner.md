#### 1a. `_to_cell(lat, lng) -> str | None`
- Replicar o helper de `oferta_academias_menores._to_cell`: `h3.latlng_to_cell(float(lat), float(lng), H3_RES_CONTRATO)`; `except (ValueError, TypeError): return None`. (Reimplementar local para não acoplar via import de função privada; helper trivial.)

#### 1b. `_centroide_hex(hex_id) -> tuple[float, float]`
- `lat, lng = h3.cell_to_latlng(str(hex_id))` → `(float(lat), float(lng))`; `except (ValueError, TypeError, KeyError): (nan, nan)`. Usado para materializar `lat`/`lng` do parquet a partir do PRÓPRIO hex (não da coord GPS bruta) — critério de aceite 3 + consistência com `share_hex` do Huff (D2).

#### 1c. `_ler_csv_tp_wh(caminho: Path, fonte: str) -> pd.DataFrame`
- `pd.read_csv(caminho, sep=";", encoding="utf-8-sig")`.
- Derivar `hex_id_res7 = _to_cell(latitude, longitude)` linha a linha (colunas `latitude`/`longitude`).
- `rede_normalizada = classificar_rede(nome)` (reuso do vocabulário de 28 tokens; fallback `independente`).
- **DROP-PII imediato:** descartar `latitude`/`longitude`/`nome`/`slug`/`cidade`/`cep`/`endereco_formatado`/`modalidades`/`atividades`/`data_coleta` após derivar hex+rede. Manter só `hex_id_res7`, `rede_normalizada`, `fonte` (literal `"totalpass"`/`"wellhub"`).
- `dropna(subset=["hex_id_res7"])`.

#### 1d. `_ler_csv_unidades(caminho: Path) -> pd.DataFrame`
- `pd.read_csv(caminho, sep=";", encoding="utf-8-sig")` (colunas `nome_unidade`/`latitude`/`longitude`/`data_coleta`).
- `rede_normalizada = caminho.stem[len("unidades_"):]` (ex.: `unidades_smart_fit.csv` → `smart_fit`). Regra do BO: rede canônica = nome do arquivo sem prefixo `unidades_` e sem extensão. Usar `.stem` (já sem `.csv`) e fatiar o prefixo `unidades_` (9 chars).
- Derivar `hex_id_res7 = _to_cell(latitude, longitude)`; DROP-PII (nome/coords/data); `fonte = "unidades"`; `dropna(subset=["hex_id_res7"])`.

#### 1e. `ingerir_csvs_concorrentes(dir_totalpass=..., dir_wellhub=..., dir_unidades=...) -> pd.DataFrame`
- Itera `sorted(dir.glob("*.csv"))` para cada uma das 3 pastas; TP/WH via 1c, Unidades via 1d.
- Concatena tudo num frame LONGO bruto com colunas `hex_id_res7`, `rede_normalizada`, `fonte`.
- **Nível 1 (intra-fonte):** antes de concatenar/logo após, `groupby(["hex_id_res7","rede_normalizada","fonte"]).size()` → `n_unidades_no_hex`; colapsa para 1 linha por `(hex_id, rede, fonte)`. Mantém `n_unidades_no_hex` (contagem bruta colapsada).
- Retorna o frame consolidado das 3 fontes (ainda com possível duplicidade INTER-fonte de `(hex_id, rede)`). **Não escreve** — é a etapa de ingestão pura (sanity de volume > 10.000 mede aqui, ANTES do dedup inter-fonte).

#### 1f. `_ler_pares_base_atual(concorrentes_path: Path) -> set[tuple[str, str]]`
- Reusar o padrão de `classificacao_rede_menor._ler_pares_concorrentes`: `pd.read_parquet(path, columns=["hex_id_res7","rede"])`, dropna, `set(zip(hex, rede))`. **Atenção de normalização:** a coluna `rede` da base atual já usa os mesmos slugs dos 28 tokens (`smart_fit`, `panobianco`, ...) — verificado (28 redes únicas casam o vocabulário). Casar direto por igualdade de string; não re-normalizar.

#### 1g. `deduplicar(df_consolidado, concorrentes_path=..., *, incluir_base_atual=True) -> pd.DataFrame`
- **Nível 2 (inter-fonte + contra base atual):** chave de dedup = `(hex_id_res7, rede_normalizada)`.
  - Ordenar por prioridade de fonte estável (para escolher a linha sobrevivente de forma determinística; ex.: precedência `unidades > totalpass > wellhub` — Unidades tem rede explícita e mais confiável). Definir `_PRECEDENCIA_FONTE = {"unidades": 0, "totalpass": 1, "wellhub": 2}`; `sort_values` por essa ordem + hex + rede; `drop_duplicates(subset=["hex_id_res7","rede_normalizada"], keep="first")`.
  - Ao colapsar inter-fonte, **somar** `n_unidades_no_hex` dos pares colapsados (groupby transform antes do drop, para preservar densidade total) OU manter o da fonte vencedora — **decisão do Planner: manter o `n_unidades_no_hex` da linha sobrevivente** (simplicidade e determinismo; a densidade fina não afeta o Huff, que usa 1 coord por hex). Documentar essa escolha no relatório.
  - **Contra base atual:** se `incluir_base_atual`, ler pares `(hex, rede)` de `concorrentes_mapeados` (1f); remover do frame denso qualquer `(hex_id_res7, rede_normalizada)` já presente na base atual (esses são "já mapeados"; não duplicar).
  - **Anexar a base atual como fonte própria:** ler `concorrentes_mapeados` (colunas `hex_id_res7`, `rede`), dedup interno por `(hex, rede)`, marcar `fonte="base_atual"`, `flag_da_base_atual=True`, `n_unidades_no_hex=1`, e `concat` ao frame denso deduplicado. Assim o parquet final = (novos das 3 fontes, sem overlap com a base) ∪ (base atual inteira). O `flag_da_base_atual` distingue as origens.
- Setar `flag_da_base_atual=False` para as 3 fontes novas.
- Retornar frame com chave `(hex_id_res7, rede_normalizada)` ÚNICA no total.

#### 1h. `_finalizar_schema(df) -> pd.DataFrame`
- Materializar `lat`/`lng` via `_centroide_hex(hex_id_res7)` (vetorizar com list-comp; ~32k linhas, aceitável).
- `versao_contrato = VERSAO_CONTRATO_CONCORRENTES_DENSOS`.
- Coerção de dtypes conforme `CONTRATO_COLUNAS_CONCORRENTES_DENSOS`; reordenar colunas na ordem canônica; `sort_values(["hex_id_res7","rede_normalizada"]).reset_index(drop=True)`.
- **`_assert_schema(df)`:** falha se houver coluna fora do contrato; falha se `hex_id_res7` ou `rede_normalizada` tiverem NaN/vazio; falha se algum `hex_id_res7` não for res-7 válido (`h3.is_valid_cell` + `h3.get_resolution == 7`) — replicar padrão `_assert_res7`.

#### 1i. `materializar(dir_..., destino=DESTINO_PARQUET_DEFAULT, *, escrever=True, incluir_base_atual=True) -> pd.DataFrame`

## Riscos técnicos
1. **Volume no CI:** o sanity `> 10.000` é sobre CSVs reais; para não violar "suíte nunca lê CSVs reais", ele fica atrás de `skipif(not dir.exists())`. Os testes de lógica usam fixtures.

3. **Desempenho do Huff com ~32k concorrentes:** `calibrar_huff_captura` já filtra por `JANELA_CATCHMENT_KM` dentro de `share_hex`; o produto 16.575 × 32k roda, mas pode levar minutos. Se lento, o filtro de janela já mitiga; NÃO alterar `huff_captura.py`. Se necessário, `executar()` pode logar progresso — sem mudar a lógica.
4. **Precedência de fonte na dedup:** determinística (`unidades > totalpass > wellhub`); documentada no relatório.
5. **Impacto no R²_oof incerto:** mais concorrentes pode dispersar share (↓R²) ou ampliar cobertura (↑pct_competitivo). NO-GO é resultado VÁLIDO (DEC-008) — o relatório deve dizer honestamente se o GO se mantém.
6. **Coluna `rede` da base atual:** confirmado que usa os mesmos slugs dos 28 tokens (28 redes únicas) — casar por igualdade direta, sem re-normalização.
