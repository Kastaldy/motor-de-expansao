## DESIGN DE UX DETALHADO (tela / layout / inputs / saídas)

Container: `with st.expander("Viabilidade do Imóvel (property-first)", expanded=effective_pin is not None):` → `render_viabilidade_ponto(...)`. Caption READ-ONLY no topo: "Stress-test de viabilidade de um imóvel real. A demanda é PREMISSA do operador, nunca prevista pela geografia. Não altera M1, carteira, plano ou artefatos oficiais."

### Seção 1 — Localização do imóvel (captura de ponto)
- Texto: o expander usa por padrão o `effective_pin` (clique/busca). Mostrar `st.markdown("**Ponto do imóvel:** \`{lat:.5f}, {lng:.5f}\`")` quando há pino.
- Campo opcional `st.text_input("Sobrescrever ponto: coordenada OU link do Google Maps", key="viab_ponto_coord_raw")`:
  - Parsing em cascata, **string pura, sem rede**: 1º `parse_coordinate_input(raw)`; se None, 2º `extract_any_coord(raw)` (link Maps) + validação `_validate_brazil_bbox`. Se ambos falharem → `st.error` com exemplos (igual ao sidebar).
  - O valor parseado **substitui** o `effective_pin` para esta análise (sem mutar session_state global do mapa).
- Se nenhum pino e campo vazio → `st.info("Clique no mapa, informe coordenada na sidebar, ou cole um link do Maps acima.")` e `return`.

### Seção 2 — Parâmetros do imóvel (formulário `st.form(key="viab_ponto_form")`)
Inputs (todos com prefixo de key `viab_ponto_*`):
- `m2` — `st.number_input("Metragem (m²)", min_value=100.0, value=1500.0, step=50.0, key="viab_ponto_m2")`.
- `aluguel_pedido` — `st.number_input("Aluguel pedido (R$/mês)", min_value=0.0, value=20000.0, step=500.0, key="viab_ponto_aluguel")`.
- **Demanda (premissa explícita — núcleo do guardrail DEC-009):**
  - Toggle `usar_p50 = st.checkbox("Usar p50 dos comparáveis como ponto de partida", key="viab_ponto_usar_p50")`.
  - `demanda_premissa = st.number_input("Demanda assumida (alunos na maturidade)", min_value=0.0, value=<default>, step=10.0, key="viab_ponto_demanda")`.
  - **Comportamento do toggle (NUNCA silencioso):** o toggle apenas PREENCHE o valor `value=` do `number_input` (via cálculo prévio de `faixa_alunos_p50` rodado fora do form OU pré-cálculo leve da faixa), deixando o número **visível e editável** antes do submit. O número enviado ao engine é SEMPRE `st.session_state["viab_ponto_demanda"]` (o que está na caixa), nunca um valor derivado de lat/lng nem de coluna do `df`. Quando o toggle está ligado mas `faixa_alunos_p50` é None → caption "p50 indisponível (sem comparáveis); informe a demanda manualmente." e o campo permanece com o último valor digitado.
  - Caption fixa abaixo: "A demanda é uma premissa SUA. A ferramenta calcula a viabilidade do número que você assumir — ela não prevê demanda pela localização."
- Opcionais (expander interno "Parâmetros avançados", defaults do engine):
  - `ticket_medio` — default `SIM_MENSALIDADE_BALCAO` (137).
  - `margem_alvo` — default 0.10 (`st.number_input` em %, convertido para fração).
- Botão `submitted = st.form_submit_button("Calcular viabilidade")`. Só roda o engine quando `submitted` (evita recomputar a cada widget; perf).

### Seção 3 — Guardrail visível
Sempre exibir, após o cálculo: `st.caption(f"Fonte da demanda: **{result.demanda_fonte}** (= valor informado pelo operador).")` — usa `ViabilidadePontoResult.demanda_fonte` (sempre `"premissa_explicita"`). Critério de aceite #2.

### Seção 4 — Cards de métricas (cenário pedido)
`st.columns(4)` (linha 1): `alunos_breakeven` (format_int; "inviável" se inf), `aluguel_teto_calculado` (R$, `_format_brl`), `margem_ebitda_pct` (% via `viabilidade.margem_ebitda_pct`), `payback_meses` (meses; "> 60 / nunca" se inf).
`st.columns(4)` (linha 2): `roic_anual` (% via `viabilidade.roic_anual`), `faturamento_mensal_steady` (R$), `ebitda_mensal` (R$), `flag_viavel` (✅/⚠️ via `viabilidade.flag_viavel`).
Realce: comparar `aluguel_pedido` vs `aluguel_teto_calculado` → caption "Aluguel pedido R$X está {abaixo|acima} do teto R$Y para margem {margem_alvo}%."

### Seção 5 — Faixa de alunos por densidade (curva m²→densidade; NÃO geográfica)
- Texto: `st.markdown("##### Faixa de alunos plausível pela metragem (comparáveis, não pela localização)")`.
- Se `faixa_alunos_p10/p50/p90` not None: `st.columns(3)` p10/p50/p90 (format_int) + caption "Baseado em `n_comparaveis` unidades de metragem similar. NÃO é previsão de demanda — é a capacidade física típica para este m²."
- Se None / `n_comparaveis` 0 ou None → `st.info("Faixa por densidade indisponível (sem comparáveis de metragem similar). Informe a demanda manualmente.")` (critério #6).

### Seção 6 — Contexto do entorno (catchment) + zona morta
- Se `pop_captacao`/`renda_per_capita_captacao` not None: `st.columns(2)` pop/renda do raio (`RAIO_CATCHMENT_KM` = 1.5). Caption "Contexto pop/renda do entorno — usado só para sinalizar zona morta, NUNCA para estimar alunos."
- `flag_zona_morta`: se True → `st.warning(f"Zona morta: {motivo_zona_morta}")`; se False → `st.success("Entorno acima dos pisos de pop/renda.")`; se None → `st.caption("Catchment indisponível (base setorial ausente para o município).")`.
- Modo degradado `setores_df=None`: mensagem clara no padrão do censo report (critério #5), sem exceção.

### Seção 7 — Grade de sensibilidade (alunos × aluguel)
- `result.grade_sensibilidade` (DataFrame colunas `alunos, aluguel, fator_aluguel, margem_liq, viavel, payback`).
- Render: **pivot table com cor** via `st.dataframe(pivot.style.background_gradient(...))` OU `pandas.pivot_table(index="alunos", columns="fator_aluguel", values="margem_liq")` formatado em %, com `st.dataframe`. Marcar viável/inviável (ex.: célula com ✓ quando `viavel`). Caption explicando eixos (linhas = alunos absolutos, colunas = fator × aluguel pedido). **Sem dependência nova** (usar `style` nativo do pandas/Streamlit; nada de matplotlib novo).

### Seção 8 — Pin do imóvel no mapa
- O pino já é renderizado no mapa principal via `search_pin`/`click_coord` (não duplicar mapa pesado dentro do expander). Documentar no caption: "O ponto analisado é o pino ativo no mapa acima." (Opção B precisaria de um mini-mapa próprio — ver delta.)
