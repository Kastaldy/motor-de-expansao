## O que foi feito

### FASE A — Confirmação empírica do poluidor (causa REAL = timestamp, NÃO estado global)

A hipótese principal do Planner (estado global `_ICON_CACHE`/`_ATLAS_CACHE` em
`competitors.py`) foi **REFUTADA**. A causa é a **hipótese ALTERNATIVA** registrada pelo
Planner: o `fpdf2` (2.8.7) carimba em cada instância de `FPDF` um `/CreationDate` (e um
`/ID` derivado dele) a partir de `datetime.now(timezone.utc)` capturado no `__init__`.

Evidências literais:

1. **O teste falha ATÉ ISOLADO** (não é cross-test pollution):
```
$ python -m pytest -q --cache-clear tests/unit/test_relatorio_pontual_censitario_export.py::test_classico_template_recente_inalterado
FAILED tests/unit/test_relatorio_pontual_censitario_export.py::test_classico_template_recente_inalterado
1 failed, 1079 warnings in 3.65s
```
```
>       assert antes == depois
E       AssertionError: assert b'%PDF-1.4\n%...8881\n%%EOF\n' == b'%PDF-1.4\n%...8881\n%%EOF\n'
E         At index 248867 diff: b'1' != b'2'
```

2. **O campo divergente é `/CreationDate`** (index 248837), e o byte do diff (248867 =
   248837+30) cai no dígito de SEGUNDOS do timestamp:
```
CreationDate fields: [b'/CreationDate (D:20260617143419Z)']
ModDate fields: []
idx of CreationDate: 248837
```

3. **`_ICON_CACHE`/`_ATLAS_CACHE` ficam VAZIOS antes E depois** (refuta o vetor de estado
   global; `_sample_result` chama `render_mapas_censitarios_combinados` sem `logos_dir`,
   logo `preload_logos` nunca roda). Forçando uma virada de segundo (`sleep 1.2`) entre as
   duas gerações, o diff aparece SEMPRE e SÓ em `/CreationDate` + `/ID`:
```
ICON_CACHE empty: True | ATLAS_CACHE empty: True
num diff bytes with 1.2s sleep: 61
 idx 248867 b'D:20260617143435Z)\n>' -> b'D:20260617143436Z)\n>'
 idx 249622 b'o 33 0 R\n/ID [<6D4C7' -> b'o 33 0 R\n/ID [<A01B4'
ICON_CACHE empty after: True | ATLAS_CACHE empty after: True
```
   (o `/ID` muda porque o fpdf2 o deriva de um hash que inclui o CreationDate)

Conclusão da Fase A: o failure é **não-determinismo de RELÓGIO DE PAREDE**, não vazamento
de estado entre testes. Um reset de cache (Fase B "preferida" do Planner) NÃO resolveria.
Seguindo a instrução do orquestrador para este exato cenário, a correção é **tornar o
teste determinístico quanto ao timestamp, SÓ em `tests/`**, sem tocar produção e sem
mascarar — exatamente a opção que o Planner autorizou ("monkeypatch do datetime.now
dentro do fpdf2").

### FASE B — Correção do determinismo (somente em `tests/`)

Criado `tests/conftest.py` (não existia) com uma fixture autouse `scope=function`
(`_freeze_fpdf_clock`) que, via `monkeypatch`, substitui o símbolo `datetime` dentro de
`fpdf.fpdf` (origem do `/CreationDate` no `__init__`) e `fpdf.output` (origem do `now` do
XMP) por uma subclasse `_FrozenDateTime` cujo `.now()` retorna um instante FIXO
(`2026-01-01T00:00:00Z`). Todo o resto do `datetime` é preservado; se `fpdf2` não
importar, a fixture é no-op gracioso. Produção (`censo_report.py`/`competitors.py`/
`censo_map.py`) **INTOCADA**.

Por que NÃO mascara: a fixture remove a ÚNICA fonte de não-determinismo legítima (o
relógio) que é irrelevante ao que o teste verifica. A assertiva `antes == depois`
continua validando de fato que gerar o template clássico no meio não muta estado
compartilhado que afete os bytes do template recente.
