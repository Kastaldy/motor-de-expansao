### B. Growth API (doc `Growth_API_Ultra_v1_0_0.pdf`, 15 páginas, lida na íntegra)
- Base URL: `https://services.ultraacademia.com.br/growth_api_ultra`. Resposta padrão: `{error, message, data}` — **sempre checar `error` antes de `data`**.
- Auth: `POST /auth/login` body `{usuario, senha}` → `data.token`. Header `Authorization: Bearer <token>`. Token expira em **1 h**; **HTTP 401 → refazer login + retentar** a requisição original (§5.4).
- Rate limit: **10 req / 5 min por IP** → **HTTP 429**; doc §6 manda **aguardar ≥30 s** + backoff exponencial; toda req é logada (IP/URL/body/login/hora).
- Query params comuns (todos os GET): `data_inicio`/`data_fim` no formato **`YYYY-MM-DD`** (opcionais). Data fora do padrão → **HTTP 422**.
- **`GET /historico-dash` (§8.2) — campos retornados (TODOS agregados por unidade/data, ZERO PII):** `unidade`, `data`, `faturamento`, `pagantes`, `conversao`, `convertidos`, `visitas`, `novos_alunos`, `ticket_medio`, `cancelados`, `churn`, `em_cobranca`, `treino_ativo`, `passagens_gympass`, `alunos_gympass`, `inadimplente`, `vendas`, `ativos_total`, `NPS`, `cancelamento_solicitado`, `passagens_totalpass`, `alunos_totalpass`, `ticket_medio_gympass`, `ticket_medio_totalpass`, `faturamento_sem_agregador`, `ticket_medio_pagantes`, `acrescimo_dias`.
- **`GET /historico-dash-view` (§8.3) — todos os campos de `/historico-dash` + 3:** `master` (string), `uf` (string), **`inauguracao` (date)**. É a fonte do `inauguracao` (gate G1 DEC-001) e do `uf`.
- **Nenhum dos dois endpoints permitidos lista PII individual** (sem `nome`/`cpf`/`email`/`celular`/`data_nascimento`/`cod_aluno`/`usuario`/`nome_usuario`). Esses campos só aparecem nos endpoints FORA DO ESCOPO (§8.4–8.10).
- **ALERTA DE ESCOPO (§10.1, contradiz a premissa pré-ciclo):** o doc afirma "os dados retornados **já estão filtrados pela unidade do login autenticado — não é possível acessar dados de outras unidades**".
