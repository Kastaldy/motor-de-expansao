1. **Política de NaN — RATIFICADA (tolerar NaN, rejeitar só fora de `[0,100]`).**
   Hexes legítimos sem score (ex.: `score_setor_2022_calibrado`/`coverage_pct_setor_2022` ausentes em UFs sem censo) não podem derrubar o app. Implementação canônica por coluna de score:
   ```python
   numeric = pd.to_numeric(df[col], errors="coerce")  # série temporária, NÃO reatribuída ao df
   mask = numeric.notna()
   if mask.any() and not numeric[mask].between(0, 100).all():
       <raise SchemaValidationError com source/coluna/min/max ofensivos>
   ```
   `pd.to_numeric(errors="coerce")` aqui é só para *ler/checar* — o resultado vive numa variável local, jamais é gravado no `df` retornado (guardrail read-only). NaN (incl. valores que viram NaN por coerção em coluna não-score) é tolerado na checagem de range; a sanidade de tipo é coberta separadamente no item 4.

3. **Método de validação do `hex_id` — `h3.is_valid_cell` vetorizado sobre os ÚNICOS, barato.**
   - h3 instalado é **v4.4.2** → usar `h3.is_valid_cell` (confirmado: `hasattr(h3,'is_valid_cell')==True`; `is_valid_cell('872830829ffffff')==True`, `is_valid_cell('lixo')==False`, não levanta exceção em garbage nem em `''`).
   - **Algoritmo:** `uniques = df["hex_id"].dropna().astype(str).unique()`; aplicar `is_valid_cell` só nos únicos (`[c for c in uniques if not h3.is_valid_cell(c)]`); se houver inválidos, levantar com os primeiros ~5 exemplos. Overhead desprezível: load é **lazy por UF** (uma partição por vez, dezenas a centenas de milhares de linhas, e os `hex_id` distintos são ~o nº de linhas mas a chamada por célula é O(1) em C; validar únicos evita reprocessar duplicatas se houver). Não usar `.apply` linha-a-linha sobre o frame inteiro.
   - Import: `import h3` no topo de `schemas.py` (h3 está no core; já importado em vários testes e em `data.py::lookup_hex_by_coord` via import tardio — aqui pode ser import de topo).

A presença das colunas obrigatórias é checada usando o **próprio `REQUIRED_COLUMNS` importado** (item de "colunas obrigatórias").

5. **API do módulo novo `schemas.py`.**
   ```python
   class SchemaValidationError(ValueError):
       """Levantada quando um frame de load do dashboard viola uma invariante de schema."""

   def validate_dashboard_frame(df: pd.DataFrame, *, source: str) -> None:
       """Valida invariantes read-only de um frame de load M1/enriquecido.
       NÃO muta df. Levanta SchemaValidationError com source/coluna/invariante ao falhar.
       Frame vazio (df.empty) é no-op (early return) — particão inexistente já é tratada a montante."""
   ```
   - `SchemaValidationError` herda de `ValueError` (compatível com o `raise ValueError` que `_read_parquet_subset` já usa para coluna faltante; o app/CI já lidam com `ValueError` no load).
   - **Toda** mensagem deve conter: `source` (arquivo/partição), o nome da coluna e a invariante violada — ex.:
     `f"[{source}] coluna 'score_priorizacao' viola faixa [0,100]: min={...}, max={...}"`,
     `f"[{source}] coluna obrigatoria ausente: 'hex_id'"`,
     `f"[{source}] coluna 'hex_id' tem {n} valores nulos (chave nao pode ser nula)"`,
     `f"[{source}] coluna 'hex_id' tem celulas H3 invalidas (ex.: {amostra})"`,
     `f"[{source}] coluna de score 'hex_score_estrutural' nao e conversivel a numerico"`.
   - Função pura, sem `st.*`, sem I/O: recebe DataFrame já carregado.

## Riscos técnicos
- **Falso positivo no caminho feliz:** se a base real tiver `hex_id` legados não-canônicos ou scores fora de faixa por dado sujo pré-existente, a validação derruba o app. Mitigação: política de NaN tolerante (item 1) + validar só únicos de `hex_id`; o Builder deve rodar `python -c "import streamlit_app"` e, se possível, exercitar `load_uf_slice` com a base real local antes de fechar. Se a base real tiver score fora de faixa hoje, isso é um achado legítimo a reportar — NÃO relaxar a faixa `[0,100]` (é a invariante do M1 §3, clip 0–100).
- **Coerção mascarando dtype:** validar **antes** de `_prepare_dataframe` é essencial; depois dele o dtype já foi coagido com `errors="coerce"` e o dtype-error viraria NaN silencioso. Plano já valida no frame cru.
- **Custo do `is_valid_cell`:** desprezível por ser lazy-por-UF e sobre únicos; não usar `.apply` no frame inteiro.
- **Divergência de lista de colunas:** mitigada importando `REQUIRED_COLUMNS` e o teste de coerência do subconjunto de scores.
